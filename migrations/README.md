# PyCRMKit Database Migrations

PyCRMKit uses Alembic to version the SQLAlchemy/PostgreSQL persistence schema.

The database URL is supplied through `PYCRMKIT_DATABASE_URL`.

```bash
export PYCRMKIT_DATABASE_URL='postgresql+psycopg://user:password@localhost/pycrmkit'
alembic upgrade head
```

Migration revisions are immutable release artifacts. Do not edit an already
released revision; add a new revision instead.

## Fresh database

For an empty PostgreSQL database:

```bash
alembic upgrade head
alembic current
alembic check
```

The `0001` baseline creates the complete persistence schema introduced by the
`0.6.x` line.

## Adopting an existing 0.6.0b2 database

`0.6.0b2` already used the same SQLAlchemy schema, but it predated Alembic.
Do **not** run the baseline create operations over those existing tables.

First verify that the existing schema matches the current ORM metadata. The
migration qualification suite performs this comparison programmatically. Only a
schema with no drift may be adopted.

Once schema parity is confirmed, stamp the database at the baseline:

```bash
alembic stamp 0001
alembic current
alembic check
```

Stamping writes migration history; it does not recreate or delete business data.

## Downgrade policy

The baseline supports:

```bash
alembic downgrade base
```

This drops the PyCRMKit persistence schema and is therefore **destructive**. It
is intended for migration qualification, development and disposable
environments. Production rollback should prefer application rollback plus a
forward corrective migration unless a specific future revision documents a
data-safe downgrade.

## Creating future revisions

After changing SQLAlchemy persistence models:

```bash
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
alembic check
```

Review every autogenerated operation before committing the revision.
