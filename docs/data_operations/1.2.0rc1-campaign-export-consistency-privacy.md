# PyCRMKit 1.2.0rc1 - LOT-31-008 Export Consistency & Privacy Qualification

**Status:** committed qualification candidate - exact-SHA CI must pass before closure.
**Baseline:** GitHub prerelease `v1.2.0b3`; PR #112 remains Draft.
**Public API:** `export_campaign_records` unchanged; no new persistence migration, snapshot guarantee or HTTP upload endpoint.

## Contract matrix

| Scope | Meaning | Exact fields |
|---|---|---|
| `direct` | Explicit membership and provenance | `campaign_id, entity_kind, entity_id, source, added_at` |
| `audience` | Deduplicated union of direct and captured Segment entities | `campaign_id, entity_kind, entity_id` |
| `sources` | Captured Segment source metadata (not recipient-level records) | `campaign_id, segment_id, segment_revision, entity_kind, attached_at, captured_at, member_count` |

All three scopes support CSV, JSON and JSONL. Page size is 1-200 (default 50); test corpus covers empty, one and 205 membership records. CSV empty output retains the header, JSON outputs `[]`, JSONL produces zero lines. JSON numeric values become text in CSV and are normalized for semantic cross-format comparison. The returned count is the number of emitted records, **not a count of unique identities under concurrent mutations**.

The export implementation iterates bounded offset pages; tests record actual page requests. This is not a measured peak-memory guarantee: RSS, query plans and performance thresholds are reserved for LOT-31-012.

## Snapshot consistency is NOT guaranteed

Exports call `OffsetPageRequest(limit=N, offset=N*k)` successively. An actual mutation between pages can shift row positions, producing missing/duplicated rows. A deterministic qualification scenario removes the first direct member immediately after page 1; the resulting output matches neither the full before-state nor the complete after-state.

**Operational requirement:** authorize the export first and perform audit-grade full extracts only under a host-controlled consistent database snapshot or a documented mutation freeze spanning both direct memberships and captured Segment sources. Otherwise mark the export **best-effort**, reconcile against an authoritative consistent extract and do not describe it as point-in-time accurate.

Streaming writers can leave a partial file on I/O errors. Write to a restricted temporary location; only atomically rename/publish it after the export returns successfully and the host validates it. Quarantine or delete failed files. No success count should be fabricated.

## CSV formula-injection boundary

The normalized `source` field can begin with `=`, `+`, `-` or `@`. CSV quoting is **not** spreadsheet formula escaping. A canonical CSV is safe for machine-to-machine field parsing but **not automatically safe to open by double-clicking it in Excel/LibreOffice**.

The `examples/data_operations/campaign_csv_spreadsheet_guard.py` example provides a consumer-side fail-closed check before spreadsheet use. It rejects potentially executable values after whitespace stripping and Unicode NFKC normalization; tests include `=1+1`, `+1+1`, `-1+1`, `@SUM(1,1)`, leading tab and full-width equals. This guard is conservative and does **not** certify every spreadsheet/import mode.

For human review, prefer an explicit data-import wizard that types *every* column as TEXT, with formula execution disabled where supported. If the guard rejects content, handle it inside an approved access-controlled workflow or create a **separate, visibly transformed spreadsheet-only copy**. Never silently prefix apostrophes or change the frozen canonical CSV fields: it would alter round-trip semantics and cross-format parity.

## Security and retention

- Direct Python DataOps calls **do not** inherit HTTP `CampaignSecurityBoundary`: the host must check authenticated principal, tenant/Campaign scope, export purpose and operation permission **before** invocation.
- UUIDs, segment identifiers, provenance and timestamps can be personal/confidential data even without names or emails. Limit access, encrypt in transit, enforce file/object ACLs, retention and deletion.
- Do not export `actor_id`, contact email/name, Communication body/recipient, arbitrary metadata, token or secret fields. Do not log raw rows or files as default troubleshooting evidence.
- The absence of these fields does not imply anonymization. App owners are responsible for consent, legal basis, data-subject rights and organizational data governance.
- Real PostgreSQL concurrency is a later gate (LOT-31-009), migrations Django LOT-31-010, adapter parity LOT-31-011, performance/RSS LOT-31-012.
