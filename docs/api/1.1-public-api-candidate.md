# PyCRMKit 1.1 Public API Freeze Candidate

**Target:** `1.1.0rc1`  
**Lot:** `PV1-LOT-007 — Segmentation Production Qualification`

PyCRMKit 1.1 extends the stable V1 contract; it does not replace it. The V1
freeze remains executable through `tests/compatibility/public_api_v1_candidate.json`.
This document freezes the additive Segmentation and Saved Query surface introduced
through the 1.1 prerelease line.

## Candidate-final namespaces

~~~text
crm.saved_queries
crm.segments
~~~

The executable source of truth is:

~~~text
tests/compatibility/public_api_v1_1_candidate.json
tests/compatibility/test_public_api_v1_1_candidate.py
~~~

It freezes module exports, repository/UoW contracts, facade methods and the
documented Segmentation/SavedQuery event types.

## Integration surface

The candidate continues to expose the optional HTTP integrations:

~~~text
FastAPI
  /segments
  /saved-queries

DRF
  segments
  saved-queries
~~~

Those transports remain adapters over the CRM facade. They do not define
independent domain semantics.

## RC rule

After `1.1.0rc1`:

- no new aggregate is added to 1.1;
- no new public facade method is added to 1.1;
- no new persistence model is introduced except to fix a release blocker;
- allowed changes are blocking correctness, security, compatibility,
  packaging, documentation or performance fixes;
- any code change that affects the candidate requires a new qualification
  cycle and, after publication, `1.1.0rc2` rather than mutating rc1.

If the candidate reaches zero blockers unchanged, the next promotion is
`1.1.0 — Segmentation & Sales Task Foundation`.
