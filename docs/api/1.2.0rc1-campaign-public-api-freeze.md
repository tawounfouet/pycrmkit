## 2. API classification

**PUBLIC - existing stable V1:** `pycrmkit.CRM`, established namespace methods and documented core domain imports; error/event and import contracts already governed by the original V1 manifest.

**PUBLIC CANDIDATE - Campaign 1.2:** `crm.campaigns` operations; the `pycrmkit.campaigns.__all__` entrypoints (including protocols and the Python DataOps module surface); Campaign DTOs, typed ID, values, enum and documented events; HTTP Campaign request/response wire behavior provided by opt-in FastAPI/DRF integrations. Changes to these surfaces require compatibility review.

**PROVISIONAL / HOST-DEFINED:** an integrating application's identity provider, authorization policy, tenant scope and operational file-retention controls. These are not public, universal PyCRMKit IAM guarantees. Any future Campaign API explicitly labelled provisional must be listed here and in the manifest before it can move to stable.

**INTERNAL:** concrete `pycrmkit.facade.campaigns.CampaignsAPI` implementation, ORM models, session/query types, private helpers, internal serializer classes and adapter-specific implementation details. The schemas' **fields** are frozen as candidate HTTP interoperability shapes without promising direct Python compatibility for private serializer class implementation.

Importability of an internal helper is not evidence of public API support. Repository/UoW protocol names exported through `pycrmkit.campaigns` remain included in the candidate public import surface, while their internal implementations remain private.

## 3. Inventory captured from v1.2.0b3 code

### Facade namespace - 26 callable methods

- Metadata and lifecycle: `create`, `get`, `list`, `update`, `activate`, `complete`, `archive`.
- Direct membership: `add_member`, `add_members`, `remove_member`, `remove_members`, `members`, `contains`.
- Audience and captured segments: `audience`, `audience_count`, `attach_segment_source`, `refresh_segment_source`, `detach_segment_source`, `segment_sources`.
- Attribution: `add_attribution`, `remove_attribution`, `attributions`.
- Communication linkage: `link_communication`, `unlink_communication`, `communication_links`, `communications`.

Every method has a snapshot of **argument names, positional/keyword-only kinds, annotations, required versus actual default values and return annotations**. The tests introspect the *bound* `crm.campaigns` namespace so implementation-only `self` is not part of the public signature.

### Domain symbols and forms

- **33 exported names** from `pycrmkit.campaigns.__all__`, tested for exact order and successful import.
- Local declared fields of `Campaign`, `CampaignUpdate`, `CampaignQuery`, `CampaignMember`, `CampaignSegmentSource`, `CampaignAttributionReference` and `CampaignCommunicationLink`.
- Four status values: `draft`, `active`, `completed`, `archived`.
- `UNSET` remains distinct from `None` for all six updatable metadata fields. `key`, `status`, `revision` and `archived_at` cannot be modified by `CampaignUpdate`.
- `CampaignId` and the domain objects remain ORM-independent.

### Campaign event contract - 16 registered types

`campaign.created`, `campaign.updated`, `campaign.activated`, `campaign.completed`, `campaign.archived`, `campaign.member_added`, `campaign.members_added`, `campaign.member_removed`, `campaign.members_removed`, `campaign.segment_source_attached`, `campaign.segment_source_refreshed`, `campaign.segment_source_detached`, `campaign.attribution_added`, `campaign.attribution_removed`, `campaign.communication_linked`, `campaign.communication_unlinked`.

The executable test checks exact `campaign.*` registration and the default registry at schema version 1. The event **payload** golden forms and runtime event-to-commit qualification are out of scope for this contract inventory; deeper tests belong to LOT-31-006.

### DataOps Python - 5 entrypoints

`import_campaign_members`, `export_campaign_records`, `iter_campaign_direct_member_records`, `iter_campaign_audience_records`, `iter_campaign_segment_source_records`.

The fixture freezes full signatures and the current import ceiling of **1,000 rows**. Direct-only member import, direct/audience/sources export, partial-commit failures and replay semantics remain unchanged. Import/export are **Python functions, not HTTP bulk file endpoints**.

### Errors

The manifest records the V1 exception class names and an **observed, bounded inventory** of Campaign error codes found in the Campaign domain/services/DataOps source. The executable check currently covers the exception hierarchy and `campaign.key.invalid` as a concrete negative case. This is not claimed to be a full golden catalogue of all adapter/HTTP error mappings; that belongs to LOT-31-003 and subsequent security/failure gates.

### Optional transport DTO shapes

- **15 FastAPI/Pydantic Campaign models:** exact field order and required-field sets checked when the FastAPI/Pydantic extra is installed.
- **17 DRF Campaign serializers:** exact declared-field order checked when Django/DRF is installed.
- No use of Django or FastAPI is required merely to import PyCRMKit's headless core.

These structural checks do **not** replace actual HTTP OpenAPI/JSON schema snapshots, HTTP status codes or serialized-response golden fixtures; those belong to LOT-31-003.

## 4. Enforcement

`tests/compatibility/test_public_api_v1_2_campaign_candidate.py` verifies:

1. V1/V1.1 manifest inheritance, without rewriting prior candidates.
2. Exact Campaign public exports and signatures, with default argument values.
3. Python DataOps signatures, domain fields and enum values.
4. Registered Campaign event names, default registry and update omission versus null.
5. V1 exception imports and a concrete Campaign error-code failure.
6. FastAPI/Pydantic fields and DRF declared serializer fields when extras exist.

`.github/workflows/public-api-freeze.yml` executes the new tests on the **source checkout** with dev extras, then runs the **same tests from an isolated installed wheel**, in a temporary directory with `python -I`, without `PYTHONPATH` or the repository's `src` path. Optional transport tests may skip on the core-only wheel by design; source-with-extras tests must exercise them.

This LOT does not change the declared project version. The stable/RC packaging and multi-version installed wheel/sdist matrix remain LOT-31-013 and 31-015/016.

## 5. Change control and gates

- Any new/removed method, parameter type/kind/default, DTO field, registered event, public export, status enum value or transport shape produces a test failure unless the manifest is deliberately updated.
- An intentional correction requires an ADR or issue, consumer impact analysis, tests, source and installed-artifact requalification and explicit GO/NO-GO; the manifest must never be silently regenerated to hide drift.
- No Campaign feature addition is authorized for this RC. Historical V1 and V1.1 fixtures remain untouched.
- Known b3 limitations remain contractual. No runtime IAM, global transactional import or consistent concurrent export snapshot is implied by the freeze.
