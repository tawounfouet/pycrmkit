# PyCRMKit 1.0 Public API Freeze Candidate

PyCRMKit `1.0.0a1` started the V1 stabilization cycle by classifying the
existing API surface instead of adding a new CRM domain capability.

`1.0.0b1` retains that candidate contract and applies the first reviewed
security hardening. The only intentional facade addition is audited webhook
secret rotation.

`1.0.0b2` keeps the CRM facade candidate unchanged and adds only
backward-compatible Import Framework controls for bounded-memory reporting.

The classification is:

```text
public
provisional
internal
```

The machine-readable candidate contract is stored at:

```text
tests/compatibility/public_api_v1_candidate.json
```

and enforced by:

```text
tests/compatibility/test_public_api_v1_candidate.py
.github/workflows/public-api-freeze.yml
```

## Classification semantics

### Public

A public candidate API is intended to enter the V1 compatibility promise.

Before `1.0.0`, corrections are still possible, but they must be explicit,
reviewed compatibility decisions rather than accidental implementation drift.

After V1 stable, removing or incompatibly changing a public API requires the
project's compatibility/deprecation policy or a major-version change.

### Provisional

A provisional API is usable and may be documented for advanced integration,
but is not yet part of the V1 compatibility promise.

Its shape may still change before V1 stable when required to improve adapter
boundaries or avoid freezing implementation detail.

### Internal

An internal API is an implementation detail.

Importability does not create a compatibility guarantee.

Names beginning with `_` are internal unless explicitly documented otherwise.

## Event serialization

The candidate `DomainEvent` envelope fields are exactly:

```text
id
type
schema_version
aggregate_type
aggregate_id
occurred_at
actor_id
correlation_id
causation_id
payload
metadata
```

`EventSerializer` must continue to round-trip this envelope and validate the
`(event_type, schema_version)` pair through an `EventRegistry`.

A semantic change to a published event payload must use an explicit
schema-version transition rather than silently changing the meaning of the same
version.

Individual Memory/SQLAlchemy repository implementation classes remain

public commitments:


This prevents the persistence representation from becoming the domain API.

Migration implementation modules remain internal. Released migration revisions
remain operational deployment artifacts and must not be rewritten.

## Compatibility gate

The Public API Freeze workflow executes the same candidate contract twice:

```text
source checkout
built wheel in a clean virtual environment
```

The installed-wheel run clears `PYTHONPATH`.

The test checks:

```text
root exports
bounded-context __all__ exports
exception hierarchy
repository protocol import paths
CRM facade namespace methods
CRMConfig / CRMContext field shapes
built-in event names
DomainEvent field/serialization shape
external_identity event names
classification bucket separation
```

## V1 qualification status

`1.0.0b1` completes the planned security/privacy hardening pass for the
candidate API and updates the executable manifest with
`crm.webhooks.rotate_secret`.

`1.0.0b2` adds reproducible performance evidence without changing the CRM
facade candidate. Its import-reporting option is additive and retains the
previous detailed-reporting default.
