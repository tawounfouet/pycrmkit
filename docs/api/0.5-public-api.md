# PyCRMKit 0.5 Candidate Public API

`0.5.0rc1` freezes the candidate Eventing & Webhooks surface before stable
promotion to `0.5.0`.

## Compatibility with 0.1–0.4

The shallow root API remains unchanged:

```python
from pycrmkit import CRM, CRMConfig, CRMContext, __version__
```

All stable CRM Core, Activity/Task/Timeline, Sales, and Communication facade
namespaces remain available.

## Events

The public event foundation includes:

```text
DomainEvent
EventRegistry
EventDefinition
EventSerializer
InProcessEventBus
```

Public event contracts are identified by exact:

```text
(event_type, schema_version)
```

`default_event_registry()` contains the built-in stable v1 event contracts
emitted by PyCRMKit through the `0.4.x` domains.

## Correlation and causation

Event-triggered work can use:

```python
crm.with_event(parent_event)
```

which propagates:

```text
actor_id       = parent.actor_id
correlation_id = parent.correlation_id or str(parent.id)
causation_id   = parent.id
```

`CRMContext.from_event(...)` exposes the same rule directly.

## Webhook registration surface

```python
subscription = crm.webhooks.register(
    url="https://example.com/hooks/crm",
    events=["contact.created", "opportunity.won"],
    signing_secret="optional-explicit-secret",
)

crm.webhooks.list(
    enabled=True,
    event_type="contact.created",
)

crm.webhooks.disable(subscription.id)
```

Subscriptions persist exact event-type filters and an enabled/disabled
lifecycle.

## Delivery surface

```python
crm.webhooks.deliver(event)
crm.webhooks.retry_due()
crm.webhooks.deliveries(...)
crm.webhooks.attempts(delivery_id)
```

A delivery is idempotently identified by:

```text
(subscription_id, event_id)
```

Delivery states are:

```text
pending
retry_scheduled
succeeded
dead_letter
```

## Automatic delivery

In `0.5.0rc1`, `CRM.memory()` enables automatic delivery by default for
committed registered CRM events:

```python
crm = CRM.memory(webhook_transport=transport)

crm.webhooks.register(
    url="https://example.com/hooks/crm",
    events=["contact.created"],
)

crm.contacts.create(display_name="Ada")
# committed contact.created is automatically matched and delivered
```

The bridge executes after the source Memory transaction commits.

Applications that need explicit/manual dispatch can opt out:

```python
crm = CRM.memory(
    webhook_transport=transport,
    webhook_auto_delivery=False,
)
```

Manual `crm.webhooks.deliver(event)` remains available in both modes.

## Request signing

Webhook requests use canonical `EventSerializer` JSON and include:

```text
X-PyCRMKit-Delivery-ID
X-PyCRMKit-Event-ID
X-PyCRMKit-Event-Type
X-PyCRMKit-Idempotency-Key
X-PyCRMKit-Timestamp
X-PyCRMKit-Signature
```

The candidate signature format is:

```text
v1=HMAC_SHA256(secret, "<unix_timestamp>.<payload_bytes>")
```

`verify_webhook_signature(...)` verifies this contract.

## Retry and failure policy

The default retry policy uses capped exponential backoff. Retryable conditions
include:

```text
timeout/network errors
HTTP 408
HTTP 425
HTTP 429
HTTP 5xx
```

Other 3xx/4xx responses are terminal for the current delivery and enter
dead-letter state.

## Transport

`WebhookTransport` is the provider-neutral transport protocol.

`StdlibWebhookTransport` is the built-in synchronous implementation. Its
default policy rejects redirects and destinations resolving to non-public IP
addresses. Private-network transport must be explicitly enabled.

## Candidate compatibility freeze

No new Eventing/Webhooks feature scope is planned between `0.5.0rc1` and
`0.5.0` stable. Stable promotion is a qualification/release decision.

Production SQL persistence, durable cross-process outbox/claiming, and
distributed delivery coordination remain later milestones.
