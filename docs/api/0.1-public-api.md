# PyCRMKit 0.1 Public API Candidate

`0.1.0rc1` starts the compatibility freeze for the `0.1.0` stable release.

## Shallow imports

The preferred root imports are:

```python
from pycrmkit import CRM, CRMConfig, CRMContext, __version__
```

Domain-specific types remain available from their bounded-context packages, for example:

```python
from pycrmkit.contacts import Contact, ContactEmail, ContactId, ContactUpdate
from pycrmkit.organizations import Organization, OrganizationId
from pycrmkit.relationships import Relationship, RelationshipEndpoint, RelationshipType
from pycrmkit.tags import Tag, TagId
from pycrmkit.custom_fields import CustomFieldDefinition, CustomFieldType
from pycrmkit.events import DomainEvent, EventId, EventType
from pycrmkit.audit import AuditEntry, AuditEntryId
```

## Candidate facade surface

```text
CRM.memory(...)
CRM.with_context(...)
CRM.config
CRM.context

CRM.contacts
CRM.organizations
CRM.relationships
CRM.tags
CRM.custom_fields
CRM.events
CRM.audit
```

This RC treats the facade names, root imports, domain IDs/value objects, repository protocols, Unit of Work contract, and versioned `DomainEvent` envelope as compatibility candidates for `0.1.0`.

Deep imports under adapter-internal modules (especially `pycrmkit.storage.memory._state`) are internal and are not compatibility promises.

## Explicit deferrals

The following are not part of the `0.1` compatibility promise:

- SQLAlchemy/PostgreSQL persistence;
- FastAPI/Django adapters;
- Activity/Timeline/Sales domains;
- webhooks or durable event delivery;
- transactional outbox;
- distributed buses;
- import/export/deduplication;
- AI/agent features.
