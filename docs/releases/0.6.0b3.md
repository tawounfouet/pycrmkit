# PyCRMKit 0.6.0b3 — Alembic / Migrations

`0.6.0b3` introduces versioned schema evolution for the SQLAlchemy/PostgreSQL
persistence line.

## Added

- Alembic migration environment and configuration;
- optional `migrations` dependency group;
- immutable `0001 — persistence baseline` revision generated from the frozen
  `0.6.0b2` SQLAlchemy metadata;
- PostgreSQL migration CI;
- empty-database `upgrade head` qualification;
- `head → base → head` lifecycle qualification;
- schema-drift comparison against `Base.metadata`;
- adoption path for existing `0.6.0b2` databases;
- explicit downgrade policy.

Install migration tooling with:

```bash
pip install "pycrmkit[migrations]"
```

## Fresh database

Set the target database:

```bash
export PYCRMKIT_DATABASE_URL='postgresql+psycopg://user:password@localhost/pycrmkit'
```

Then apply the schema:

```bash
alembic upgrade head
alembic current
alembic check
```

The migration version at this release is:

```text
0001 — persistence baseline
```

## Existing 0.6.0b2 database

`0.6.0b2` introduced the production-reference PostgreSQL schema before Alembic
history existed.

The migration suite verifies that a database created from the `0.6.0b2`
SQLAlchemy metadata has no structural drift from revision `0001`.

For such a verified database, adoption is performed with:

```bash
alembic stamp 0001
alembic current
alembic check
```

`stamp` records migration history without recreating tables or destroying
existing CRM data.

A database with schema drift must be reconciled before it is stamped.

## Downgrade policy

Revision `0001` implements `downgrade()` back to `base`, and the CI verifies
that the schema can subsequently be upgraded to `head` again.

However, downgrading the baseline is **destructive**: the PyCRMKit persistence
tables are dropped.

It is therefore intended for disposable environments, migration qualification
and development. Production rollback should normally prefer application
rollback plus a forward corrective migration unless a later revision explicitly
documents a data-safe downgrade.

## Migration immutability

Released revisions are immutable.

After a persistence-model change, create a new revision:

```bash
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
alembic check
```

Every autogenerated revision must be reviewed before commit.

Generated files under `migrations/versions/` are excluded from Ruff formatting
so their reviewed migration operations remain stable; they are still compiled
and executed against PostgreSQL in CI.

## Qualification

The release passes:

- Alembic `upgrade head` from an empty PostgreSQL database;
- schema parity with current SQLAlchemy metadata;
- `downgrade base` followed by re-upgrade;
- `0.6.0b2` schema adoption without data loss;
- direct `alembic check`;
- migration Python compilation;
- PostgreSQL 17 persistence tests;
- Python 3.11, 3.12 and 3.13;
- Ruff;
- strict mypy;
- documentation build;
- package build;
- aggregate CI.
