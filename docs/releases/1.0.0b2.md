# PyCRMKit 1.0.0b2 — Performance Baseline

`1.0.0b2` establishes the first reproducible V1 performance baseline while
preserving the public API freeze and security/privacy hardening delivered by the
previous V1 candidates.

## Benchmarked paths

The release baseline covers:

```text
Contact creation
Contact search
Timeline retrieval
bulk import
repository query pagination
event publication
```

The standard-library benchmark runner records median/min/max latency per logical
operation across one warm-up and five measured samples.

## Bounded-memory improvement

The Import Framework gains an additive high-volume option:

```python
ImportPipeline(..., retain_row_results=False)
```

With summary mode enabled:

```text
rows_read           exact
rows_created        exact
rows_updated        exact
rows_skipped        exact
duplicates          exact
validation_errors   exact
row_results         not retained
```

The existing default remains `True`, so detailed import reports remain
backward compatible.

## Pagination qualification

Performance-contract tests lock the following V1 behavior:

```text
OffsetPageRequest.DEFAULT_LIMIT = 50
OffsetPageRequest.MAX_LIMIT = 200
repository list/search contracts require a page object
SQLAlchemy page queries apply LIMIT/OFFSET in SQL
public Contact search defaults to a bounded page
```

The in-memory adapter is explicitly treated as a development/test backend, not
as a production-scale persistence claim.

## Performance evidence

The dedicated `Performance Baseline` workflow executes the benchmark from:

```text
source checkout
built wheel in a clean virtual environment
```

and uploads:

```text
performance-baseline-source.json
performance-baseline-wheel.json
```

The configured ceilings are release-regression guardrails, not SLAs.

## Public API candidate delta

No new CRM facade method is added.

The Import Framework receives only additive optional reporting behavior:

```text
ImportPipeline.retain_row_results
ImportReport.retain_row_results
```

with backward-compatible defaults.

## Scope boundary

This beta does not claim production latency or throughput guarantees for a
specific database, cloud, HTTP stack or deployment topology.
