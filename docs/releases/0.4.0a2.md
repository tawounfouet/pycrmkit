# PyCRMKit 0.4.0a2 — Email Provider Protocol

## Objective

Introduce the provider-neutral email transport boundary without implementing a concrete network adapter.

## Added

- `communication/email/provider.py` with runtime-checkable `EmailProvider`.
- `EmailProviderResult` carrying provider name, provider message ID, immutable metadata, failure code, and immediate transport status.
- `communication/email/messages.py` with immutable `EmailMessage`.
- `communication/email/services.py` with `EmailDeliveryService`.
- Explicit mapping from provider `accepted/failed` outcomes to the existing `DeliveryAttempt` aggregate.
- Unit tests covering structural protocol compatibility, immutable metadata, provider-result invariants, queued-intent enforcement, acceptance/failure mapping, and invalid provider results.
- Installed-package smoke coverage for the new contract while replaying stable 0.2/0.3 behavior.

## Compatibility

The stable root package and CRM facade namespaces remain unchanged. The email provider contract is available from `pycrmkit.communication` and `pycrmkit.communication.email`.

## Architectural boundary

This alpha adds no network dependency and no concrete provider. SMTP and templates remain deferred to `0.4.0b1`; Resend remains deferred to `0.4.0b2`.

Provider acceptance remains distinct from final mailbox delivery. Delivery/open/click/bounce history remains a `0.4.0rc1` concern.
