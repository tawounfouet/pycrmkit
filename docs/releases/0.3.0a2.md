# PyCRMKit 0.3.0a2 — Opportunities

This alpha adds the Opportunity domain as the second Sales Foundation increment.

## Added

- typed `OpportunityId` and `OpportunityStatus`;
- statuses `open`, `won`, `lost`, `cancelled`;
- name, Contact/Organization linkage, opaque pipeline/stage references;
- Decimal-safe estimated value + normalized currency through `Money`;
- optional Decimal probability in `[0, 1]`;
- expected close date and owner;
- backend-neutral `OpportunityQuery`, `OpportunityRepository`, and `OpportunityService`;
- official copy-isolated `MemoryOpportunityRepository`;
- Opportunity participation in `MemoryStore` and `MemoryUnitOfWork`;
- creation-only `crm.opportunities.create(...)` facade;
- post-commit `opportunity.created` event and privacy-conscious audit entry;
- unit, repository-contract, UoW, facade, E2E, public API, and installed-wheel smoke qualification.

## Deliberately deferred

`0.3.0a2` does not define Pipeline or Stage aggregates and does not validate stage transitions.

```text
0.3.0b1 → Pipeline / Stage / transition policies
0.3.0b2 → atomic Lead → Opportunity conversion
```

The facade therefore does not expose `move`, `mark_won`, `mark_lost`, `get`, or `list` yet. The domain/service layer already preserves won/lost/cancelled lifecycle semantics so persistence adapters can qualify state fidelity before the public Pipeline API is frozen.
