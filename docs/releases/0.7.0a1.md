# PyCRMKit 0.7.0a1 — Schemas & Dependency Bridge

`0.7.0a1` opens the FastAPI integration line without coupling the PyCRMKit
domain to FastAPI or Pydantic.

This alpha delivers the transport and dependency foundations required by the
future routers.

## Added

- optional `fastapi` installation extra;
- `pycrmkit.integrations.fastapi.dependencies`;
- `pycrmkit.integrations.fastapi.schemas`;
- `pycrmkit.integrations.fastapi.errors`;
- `pycrmkit.integrations.fastapi.pagination`;
- Pydantic request/response schemas for Contacts, Organizations,
  Relationships, Activities, Tasks, Leads, Opportunities and Timeline;
- explicit schema → domain DTO/value-object conversion;
- explicit domain entity → response-schema conversion;
- request metadata bridge for `X-Actor-ID` and `X-Correlation-ID`;
- offset pagination bridge using the stable `OffsetPageRequest`/`Page`
  primitives;
- typed `ErrorResponse` preserving public PyCRMKit error codes and context.

## Architecture

The integration keeps the dependency direction one-way:

```text
FastAPI / Pydantic
       ↓
PyCRMKit integration schemas
       ↓
CRM facade / DTOs / Value Objects
       ↓
Domain
```

The domain does not import FastAPI or Pydantic.

Importing the core package remains valid without the FastAPI extra installed:

```python
import pycrmkit
```

FastAPI support is explicitly opted into:

```bash
pip install "pycrmkit[fastapi]"
```

## Dependency bridge

`CRMDependency` accepts a factory for the application's already-wired CRM
instance.

It does not decide whether the application uses Memory, SQLAlchemy,
PostgreSQL or a custom adapter.

```python
from typing import Annotated

from fastapi import Depends, FastAPI

from pycrmkit import CRM
from pycrmkit.integrations.fastapi import CRMDependency

crm = CRM.memory()
get_crm = CRMDependency(lambda: crm)

app = FastAPI()

@app.get("/example")
def example(current: Annotated[CRM, Depends(get_crm)]):
    return {
        "actor_id": current.context.actor_id,
        "correlation_id": current.context.correlation_id,
    }
```

When present, `X-Actor-ID` and `X-Correlation-ID` are projected through the
stable `CRM.with_context(...)` API. Missing headers preserve the base CRM
context.

## Schemas are transport objects

Pydantic models are not domain Entities.

For example:

```python
payload = ContactCreateRequest(
    first_name="Ada",
    last_name="Lovelace",
)

contact = crm.contacts.create(**payload.to_domain_kwargs())
response = ContactResponse.from_domain(contact)
```

PATCH-like request schemas preserve the existing PyCRMKit distinction between:

```text
field omitted       → domain UNSET
field = null        → explicit clear, where the domain allows it
field = value       → explicit replacement
```

Non-nullable domain fields are rejected if explicitly supplied as null.

## Pagination

HTTP pagination uses the same bounded offset semantics as repository/facade
pagination:

```text
limit: 1..200
offset: >= 0
default limit: 50
```

`PageResponse` exposes:

- `items`;
- `limit`;
- `offset`;
- `total`;
- `has_next`;
- `has_previous`.

## Error payload foundation

`ErrorResponse.from_error(...)` converts a public `PyCRMKitError` into:

```json
{
  "code": "contact.email.invalid",
  "message": "invalid input",
  "context": {}
}
```

HTTP status mapping and application-level exception handlers are intentionally
deferred to `0.7.0b2`.

## Qualification

The alpha verifies:

- FastAPI dependency injection with request headers;
- preservation of existing CRM context;
- Pydantic request validation;
- schema → domain conversion;
- domain → response serialization;
- PATCH omission/explicit-clear semantics;
- pagination bounds and page metadata;
- schema execution against the stable CRM facade;
- core import without FastAPI;
- Python 3.11, 3.12 and 3.13;
- Ruff;
- strict mypy;
- Docs;
- Build;
- PostgreSQL/Migrations/Persistence regression gates.

