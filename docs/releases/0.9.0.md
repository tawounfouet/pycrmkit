# PyCRMKit 0.9.0 — Data Operations Stable

`0.9.0` promotes the fully qualified Data Operations release candidate to a
stable V0.9 line without adding new functional scope.

## Stable Data Operations line

The stable journey is:

```text
CSV / JSON / JSONL
        ↓
Read / Map / Normalize / Validate
        ↓
application-owned persistence
        ↓
duplicate candidate detection
        ↓
score + conflicts + provenance
        ↓
explicit candidate review
        ↓
explicit primary selection
        ↓
transactional Contact merge
        ↓
audit + external identity preservation
        ↓
normalized export
```

## Import contract

The stable import pipeline remains:

```text
Read
 ↓
Map
 ↓
Normalize
 ↓
Validate
 ↓
Deduplicate
 ↓
Persist
 ↓
Report
```

The framework does not impose one Contact persistence policy. Applications
provide an `ImportPersister` implementation appropriate to their own creation
and update semantics.

The documented report counters remain:

```text
rows_read
rows_created
rows_updated
rows_skipped
duplicates
validation_errors
```

## Format contract

The stable V0.9 exchange formats are:

```text
CSV
JSON
JSONL
```

CSV remains scalar/tabular and preserves source order and duplicate rows.

JSON and JSONL preserve JSON-native nested values.

Structural source failures remain explicit typed validation errors rather than
being silently skipped.

## Deduplication contract

The stable candidate engine supports:

```text
normalized email
normalized phone
full name
organization
postal address
external identity
custom identifier
```

The default policy remains deterministic and explainable.

Candidate outcomes are:

```text
no_match
review
duplicate
conflict
```

Automatic import duplicate detection remains conservative: only one
unambiguous candidate at the duplicate threshold is auto-reported as a
duplicate. Multiple qualifying candidates are not silently selected.

## Merge contract

The caller explicitly supplies the primary and duplicate Contact IDs.

The default merge policy remains conservative:

```text
primary email conflict   → reject
primary phone conflict   → reject
custom-field conflict    → reject
duplicate provenance     → required
```

The merge transaction preserves:

```text
activity references
relationships
tags
custom fields
external identities
audit trail
dedup provenance
```

The duplicate Contact is archived rather than physically deleted.

No automatic primary-record selection is introduced by the stable promotion.

## External identity contract

The upstream-record key remains:

```text
(system, external_id)
```

A unique upstream record belongs to one PyCRMKit entity.

Stable persistence qualification covers the already documented Memory,
SQLAlchemy/PostgreSQL and Django adapters.

## Functional delta from rc1

None.

The stable release changes package version and stable
documentation/compatibility metadata only, then reruns the complete release
gate.

## Scope boundary

`0.9.0` stabilizes **Contact-oriented Data Operations**.

It does not introduce:

```text
organization merge execution
automatic primary selection
fuzzy or ML-based matching
new import persistence policy
new persistence schema
new transport surface
```

PyCRMKit remains pre-`1.0.0`; the broader public API freeze is a V1 milestone.
