# PyCRMKit 0.9.0b3 — Merge

`0.9.0b3` completes the V0.9 data-operation building blocks with conservative,
transactional Contact merge execution.

## Delivered

```text
dedup/merge.py
dedup/services.py
```

## Merge contract

- Explicit primary-record selection.
- Duplicate provenance required by default.
- Atomic Unit-of-Work execution.
- Contact profile/contact-point consolidation.
- Activity reassignment.
- Active relationship reassignment.
- Direct primary↔duplicate relationship closure.
- Tag union.
- Configurable custom-field conflict resolution.
- External-identity preservation and ownership transfer.
- Duplicate archival.
- Append-only merge audit.
- Full provenance retained in `MergeResult`.

## Conservative defaults

```text
primary email conflict   → reject
primary phone conflict   → reject
custom field conflict    → reject
duplicate provenance     → required
```

Applications may explicitly select `keep_primary` or `keep_duplicate` for the
three supported conflict classes.

## Transaction safety

All repository changes occur in one Unit of Work. Tests deliberately trigger a
custom-field conflict after earlier merge stages have already mutated the
working transaction and verify that every mutation is rolled back.

## Audit privacy

The persisted audit keeps score/decision/signal names and conflict summaries,
but does not duplicate matched PII values. Full evidence remains available from
the returned `DedupProvenance`.

## Scope boundary

No organization merge executor or complete Data Operations E2E application
journey is added in this beta.
