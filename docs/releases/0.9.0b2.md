# PyCRMKit 0.9.0b2 — Deduplication

`0.9.0b2` replaces the provisional import deduplication hook with an
explainable, configurable candidate-detection engine.

## Delivered

```text
dedup/candidates.py
dedup/matchers.py
dedup/scoring.py
dedup/conflicts.py
dedup/provenance.py
```

## Signals

The engine qualifies all signals scheduled for the V0.9 roadmap:

```text
normalized email
normalized phone
full name
organization
postal address
external identity
custom identifier
```

## Decision model

Candidate evaluation produces one of:

```text
no_match
review
duplicate
conflict
```

The default score policy is deterministic, additive by unique signal type,
capped at 100 and configurable.

An exact external identity or custom identifier reaches the default duplicate
threshold by itself. Email or phone alone remain review-level evidence unless
combined with additional signals.

## Conservative auto-detection

The `ImportDeduplicator` bridge reports an automatic duplicate only when exactly
one candidate reaches the duplicate decision.

Ambiguous multiple high-confidence candidates are not automatically selected.

## Conflicts

Contradictory evidence is retained separately from positive matches. Custom
identifier disagreement within the same namespace is blocking; other supported
signal disagreements are preserved as warnings for review.

## Provenance

`DedupProvenance` exposes candidate ID, score, decision, matched evidence and
conflicts. Its `as_dict()` representation is intended for future review/audit
workflows.
