# PyCRMKit 0.5.0rc1 — Eventing & Webhooks E2E

This release candidate integrates the complete `0.5.x` Eventing & Webhooks
feature line before stable promotion.

## Integrated scenario

The candidate qualifies the roadmap scenario end to end:

```text
create contact
      ↓
commit source transaction
      ↓
emit contact.created
      ↓
match active subscription
      ↓
serialize canonical payload
      ↓
sign HMAC request
      ↓
deliver
      ↓
record response
      ↓
schedule retry on retryable failure
      ↓
retry_due()
      ↓
inspect delivery + attempt history
```

The E2E qualification exercises a first HTTP 503 response followed by a
successful HTTP 204 retry.

## Automatic bridge

Committed registered CRM events are now bridged automatically into the webhook
delivery engine when automatic delivery is enabled.

`CRM.memory(...)` enables this behavior by default. It can be disabled with:

```python
CRM.memory(webhook_auto_delivery=False)
```

Explicit `crm.webhooks.deliver(event)` remains supported.

The bridge instance is shared by `CRM.with_context(...)` and
`CRM.with_event(...)` facade views so lightweight contextual views do not
duplicate event subscriptions.

## Memory transaction sequencing

The Memory adapter now publishes synchronous post-commit events only after the
store transaction boundary has been released.

This preserves the core guarantee that domain state commits before external
event handling while allowing a webhook subscriber to open a fresh Unit of
Work against the committed state.

A repeated `commit()` on the same Memory Unit of Work is rejected explicitly.

## Candidate scope

The candidate freezes the `0.5.x` surface established across:

```text
0.5.0a1 Event Registry & Serialization
0.5.0a2 Correlation & Causation
0.5.0b1 Webhook Registrations
0.5.0b2 Webhook Delivery Engine
0.5.0rc1 Eventing & Webhooks E2E
```

## Compatibility

Stable `0.1`–`0.4` root and facade contracts remain unchanged.

No new Eventing/Webhooks feature scope is planned before `0.5.0` stable.

## Deferred

The release candidate does not add SQLAlchemy/PostgreSQL, a durable
cross-process outbox, database delivery claiming, distributed worker
coordination, FastAPI, or Django integration. Those remain later roadmap
milestones.
