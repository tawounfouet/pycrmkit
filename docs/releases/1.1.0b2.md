## Snapshot Segments

A Snapshot freezes a population once:

~~~text
Dynamic Segment / QueryExpression
              ↓
        evaluate at T0
              ↓
        Snapshot Segment
              ↓
      stored memberships
              ↓
underlying CRM changes after T0
              ↓
Snapshot remains unchanged
~~~

Applications can either freeze a portable expression directly with
`crm.segments.create_snapshot(...)` or freeze the current membership of an
existing Segment with `crm.segments.snapshot(...)`.

Snapshot creation and materialization happen inside one Unit of Work.

## Bulk membership

Static Segments gain bounded transactional operations:

~~~python
crm.segments.add_members(segment.id, references)
crm.segments.remove_members(segment.id, references)
~~~

The public batch limit is 1000 references. Duplicate references in one add
batch are rejected before writes begin. Snapshot and Dynamic memberships remain
non-writable.

## Django persistence

The Django adapter now persists:

~~~text
Segment
SegmentMember
SavedQuery revisions
~~~

and exposes the optional Segmentation/SavedQuery capabilities through
`DjangoTransactionBridge`.

The Django migration chain advances to:

~~~text
0001_initial
    ↓
0002_external_identity
    ↓
0003_segmentation
~~~

## Django query execution boundary

The current Django bridge owns Contact and Organization persistence, so the
Django Segment query executor supports those entity kinds.

Queries that require Lead, Opportunity, Tag or Custom Field backing state are
rejected explicitly rather than evaluated with incomplete semantics.

## Events

New event types:

~~~text
segment.snapshot_created
segment.members_added
segment.members_removed
~~~

Existing single-member events remain unchanged.

## Compatibility

- Existing Static and Dynamic Segment APIs remain unchanged.
- Memory remains the semantic reference adapter.
- SQLAlchemy/PostgreSQL behavior from 1.1.0b1 remains supported.
- Snapshot membership is represented through the existing SegmentMember
  persistence contract; no query AST is persisted on the Snapshot aggregate.
- Django remains an optional integration.
