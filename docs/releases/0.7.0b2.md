# PyCRMKit 0.7.0b2 — OpenAPI & Error Mapping

`0.7.0b2` completes the FastAPI beta contract before the PostgreSQL-backed
release-candidate application.

## Objective

Provide a predictable REST error surface and document it in OpenAPI without
coupling the PyCRMKit core to FastAPI.

## Error model

Every mapped error is serialized as:

```json
{
  "code": "resource.not_found",
  "message": "resource not found",
  "context": {}
}
```

The transport model remains `ErrorResponse`.

## Status mapping

```text
ValidationError       422
NotFoundError         404
ConflictError         409
DuplicateError        409
InvalidStateError     409
RepositoryError       500
IntegrationError      502
PyCRMKitError         500
```

## FastAPI validation

`RequestValidationError` is normalized into:

```text
code    = request.validation_error
status  = 422
shape   = ErrorResponse
```

Validation details intentionally omit the original submitted input.

## Application integration

```python
from fastapi import FastAPI

from pycrmkit import CRM
from pycrmkit.integrations.fastapi import (
    create_crm_router,
    install_error_handlers,
)

crm = CRM.memory()
app = FastAPI()

install_error_handlers(app)
app.include_router(create_crm_router(lambda: crm), prefix="/crm")
```

## OpenAPI

Public routes declare typed errors with status-specific examples. The
integration exposes reusable response groups for create/list/read/mutation
operations.

Qualification is selective instead of snapshotting the complete OpenAPI
document. Tests freeze important public contracts such as:

```text
method
path
request schema
success response schema
error status
ErrorResponse schema
examples
```

## Architecture

The error bridge does not alter dependency direction:

```text
FastAPI
  ↓
integration errors / routers
  ↓
CRM facade
  ↓
domain
```

No domain module imports FastAPI.

## Qualification

The beta verifies:

- domain error status mapping;
- request-validation normalization;
- domain validation through a real router;
- not-found through a real router;
- invalid-state conflict through a real router;
- validation payload input-redaction behavior;
- OpenAPI success and error schemas;
- OpenAPI examples;
- existing FastAPI router E2E with installed handlers;
- Python 3.11/3.12/3.13, Ruff, strict mypy, docs, build and persistence
  regression gates.
