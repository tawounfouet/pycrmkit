# PyCRMKit 1.1.0b3 — Segmentation Data Operations & API Integration

This release implements **PV1-LOT-006**.

## Delivered

~~~text
Segmentation domain
      ↓
Data Operations bridge
      ├── ImportReader → Static Segment membership
      └── Segment population → CSV / JSON / JSONL exporters

CRM facade
      ↓
HTTP integration
      ├── FastAPI
      └── Django REST Framework
~~~

## Segment Data Operations

The provider-neutral import framework can now target Static Segment membership
through:

~~~python
from pycrmkit.importers import CSVReader
from pycrmkit.segments import import_segment_members

report = import_segment_members(
    crm.segments,
    segment.id,
    CSVReader("segment-members.csv"),
)
~~~

The canonical membership input is:

~~~text
entity_id      required UUID
entity_kind    optional when it matches the Segment entity kind
~~~

Membership export is intentionally format-neutral:

~~~python
from pycrmkit.exporters import CSVExporter
from pycrmkit.segments import iter_segment_membership_records

CSVExporter("members.csv").write(
    iter_segment_membership_records(crm.segments, segment.id)
)
~~~

The same record stream works with JSON and JSONL exporters.

Dynamic exports are live. A reproducible export should use an immutable Snapshot
Segment first.

## FastAPI

The composite `create_crm_router(...)` now mounts:

~~~text
/segments
/saved-queries
~~~

The Segments surface covers definition creation/list/read/archive, population
evaluation, bounded bulk membership mutation and Snapshot creation.

The Saved Queries surface covers create/list/read/update/archive, revision
history and execution.

All routes remain facade-backed. FastAPI routers do not reach through to
repositories, SQLAlchemy sessions or ORM models.

## Django REST Framework

`create_drf_router()` now also registers:

~~~text
segments
saved-queries
~~~

The DRF surface mirrors the same application boundary:

~~~text
HTTP
  ↓
serializer / ViewSet
  ↓
CRM facade
  ↓
domain service
  ↓
selected persistence adapter
~~~

## Compatibility

- Existing V1 HTTP routes remain unchanged.
- Memory/SQLAlchemy/Django Segmentation contracts remain unchanged.
- File formats remain adapters around provider-neutral records; the Segment
  domain does not depend on CSV/JSON/JSONL.
- Snapshot immutability and bulk-membership bounds introduced in 1.1.0b2 remain
  authoritative.
