# PyCRMKit 0.3.0b2 — Lead Conversion

This beta closes the missing transaction between the Lead and Opportunity
domains.

## Added

- public `crm.leads.convert(...)`;
- cross-aggregate `LeadConversionService`;
- atomic Lead state transition + Opportunity creation within one Unit of Work;
- conversion provenance linking a converted Lead to its Opportunity;
- domain-level idempotent retry through idempotency key + request fingerprint;
- conflicting replay detection with typed `ConflictError`;
- automatic entry into a supplied Pipeline's initial Stage;
- initial-stage default probability propagation;
- post-commit `opportunity.created` and `lead.converted` events;
- transactional audit history for both mutations;
- unit, facade, rollback, transport-retry, end-to-end, public API, and
  installed-package smoke coverage.

## Idempotency contract

```text
first request
    → create Opportunity
    → mark Lead converted
    → commit

same key + equivalent request
    → return same Opportunity
    → no duplicate event/audit

same key + conflicting request
    → ConflictError

different key after conversion
    → InvalidStateError
```

When the caller omits `idempotency_key`, PyCRMKit derives a deterministic key
from the Lead identity, so a Lead still cannot be converted twice through the
public workflow.

## Transaction semantics

A failed conversion before commit leaves both Lead and Opportunity state
unchanged. The Memory adapter proves this with one shared transaction snapshot.

Event subscribers still run synchronously after commit. Therefore subscriber
failure cannot roll back committed domain state. A retry of the conversion
command returns the committed Opportunity instead of creating a duplicate.
Durable event-delivery retry/outbox behavior remains deferred to the Eventing &
Webhooks roadmap.

## Compatibility

- stable `0.1` and `0.2` public contracts remain unchanged;
- `crm.leads` gains only the additive `convert(...)` method;
- `crm.opportunities.create/move` and `crm.pipelines.define/get/list` retain the
  `0.3.0b1` surface;
- direct Opportunity lifecycle methods remain outside the facade.
