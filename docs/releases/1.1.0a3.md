# PyCRMKit 1.1.0a3 — Sales Task Ergonomics & Business Calendar Foundation

This release implements **PV1-LOT-003**.

## Delivered

~~~text
TaskType
├── GENERAL
├── CALL
└── EMAIL

Sales Work Queue
├── Overdue
├── Today
├── Upcoming
└── Unscheduled

BusinessCalendar
├── IANA timezone
├── working weekdays
├── working windows
├── holidays
├── date overrides
├── business-day arithmetic
├── default due time
└── runtime registry
~~~

### Task compatibility

Existing V1 Task semantics are preserved. `TaskType.GENERAL` is the migration
default and the SQLAlchemy migration backfills existing rows to `general`.

The existing Task event names and payload shape remain compatible.

### Work queues

- `today()` uses local half-open day bounds;
- `upcoming()` starts at the next local day;
- `overdue()` keeps the strict V1 `due_at < now` rule;
- `unscheduled()` exposes unresolved Tasks without `due_at`;
- terminal Tasks are excluded from operational queues;
- filtering and ordering are adapter-side, not unbounded in-memory projections.

### Business Calendar

The first calendar implementation is runtime configuration. It resolves
business-day policy into absolute Task `due_at` values and does not mutate
already-scheduled Tasks when a calendar revision changes.

### Persistence

SQLAlchemy gains a `task_type` column through migration `0004`, backfilled
to `general`.

### Deferred

Full Cadence/Sequence execution remains outside the mandatory 1.1 scope.

The next roadmap milestone is **1.1.0b1 — SQLAlchemy/PostgreSQL Segmentation**.
