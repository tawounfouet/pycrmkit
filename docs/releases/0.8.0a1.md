# PyCRMKit 0.8.0a1 — Django Application Bridge

`0.8.0a1` begins the native Django integration line without changing
PyCRMKit's domain architecture.

## Objective

Make PyCRMKit adoptable inside Django projects while preserving:

```text
Domain
  ↓
Repository Protocol
  ↓
Adapter
```

Django remains an optional adapter, not the definition of CRM business state.

## Delivered

```text
PyCRMKitDjangoConfig
Django 5.2 LTS optional dependency
Contact persistence models
Organization persistence models
Relationship persistence model
DjangoContactRepository
DjangoOrganizationRepository
DjangoRelationshipRepository
shared contract-suite qualification
strict django-stubs typing
dedicated optional-extra CI gate
```

## Model boundary

The core invariant is:

```text
Contact domain entity        ≠ ContactModel
Organization domain entity   ≠ OrganizationModel
Relationship domain entity   ≠ RelationshipModel
```

Mapping is explicit inside the adapter. Django QuerySets and model instances do
not leak into repository protocols.

## Repository equivalence

The first Django repositories replay the same executable contracts already used
by Memory and SQLAlchemy.

This means the alpha verifies equivalent observable behavior for:

```text
save / get / find
missing-record errors
replacement semantics
normalized searches
archive/end lifecycle visibility
deterministic pagination
relationship query semantics
```

## Dependency boundary

```text
pip install pycrmkit
```

still does not require Django.

Django consumers use:

```bash
pip install "pycrmkit[django]"
```

then:

```python
INSTALLED_APPS = [
    "pycrmkit.integrations.django.apps.PyCRMKitDjangoConfig",
]
```

## Alpha limitations

The following are deliberately **not** part of `0.8.0a1`:

```text
Django migrations
Django transaction/UoW bridge
Django admin helpers
DRF
reference Django application
Django/PostgreSQL E2E
```

They remain assigned to the later milestones in the V1 roadmap.
