# PyCRMKit 0.6.0a1 — SQLAlchemy Foundation

`0.6.0a1` opens the Persistence Foundation milestone without changing the domain-first dependency direction.

## Added

- optional `sqlalchemy` dependency group;
- adapter-owned declarative `Base` and deterministic metadata naming convention;
- explicit `SQLAlchemyMapper` domain/ORM mapping boundary;
- normalized ORM persistence models for CRM Core, Activities, Sales, Communication, Audit and Webhooks;
- contact/organization value-object tables and query-oriented link tables;
- persistence coverage for communication delivery history and reliable webhook delivery state introduced in `0.4.x` and `0.5.x`;
- SQLAlchemy foundation tests.

## Architectural constraints

The core remains importable without SQLAlchemy. Domain entities do not inherit from ORM models, and normal PyCRMKit public APIs do not expose SQLAlchemy sessions or model instances.

This release does **not** yet provide repository implementations, a SQLAlchemy Unit of Work, PostgreSQL qualification or Alembic migrations. Those remain the scope of `0.6.0a2` through `0.6.0rc1`.
