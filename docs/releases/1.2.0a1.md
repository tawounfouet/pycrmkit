# PyCRMKit 1.2.0a1 — Campaign Foundations & Metadata

This release implements **PV1-LOT-008**, the first Campaign Metadata increment
after PyCRMKit 1.1.0 stable.

## Delivered

~~~text
Campaign
    ↓
CampaignRepository
    ↓
CampaignService
    ↓
MemoryCampaignRepository
    ↓
crm.campaigns
~~~

### Domain

- typed CampaignId;
- normalized stable Campaign key;
- CampaignStatus: Draft, Active, Completed, Archived;
- optional description and start/end metadata;
- optional owner reference;
- optimistic revision;
- extensible metadata;
- explicit activate / complete / archive lifecycle.

### Memory adapter

- copy-isolated Campaign repository;
- unique-key protection;
- deterministic pagination;
- status/owner filtering;
- archived-record filtering;
- transactional participation in MemoryUnitOfWork.

### Facade

~~~python
crm.campaigns.create(...)
crm.campaigns.get(...)
crm.campaigns.list(...)
crm.campaigns.update(...)
crm.campaigns.activate(...)
crm.campaigns.complete(...)
crm.campaigns.archive(...)
~~~

### Events

~~~text
campaign.created
campaign.updated
campaign.activated
campaign.completed
campaign.archived
~~~

## Compatibility

PyCRMKit 1.1 remains the stable compatibility baseline. 1.2.0a1 is additive.

The historical V1.1 freeze and stable-release evidence remain executable
without pinning the current development package to version 1.1.0.

## Explicit boundary

This is **Campaign metadata**, not a campaign engine or marketing automation
platform.
