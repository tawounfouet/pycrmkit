# PyCRMKit 0.4.0b2 — Resend Adapter

## Objective

Add the second concrete email provider without changing the provider-neutral Communication domain introduced in `0.4.0a1/a2`.

## Added

- `providers/email/resend.py`.
- Optional `resend>=2.47,<3` dependency through the `resend` extra.
- `ResendConfig` and `ResendEmailProvider`.
- Mapping of sender, named recipients, subject, text/HTML content, intent header, and idempotency key.
- Mapping of Resend response `id` into `provider_message_id`.
- Selected response metadata such as request ID and rate-limit information.
- Resend SDK/API error normalization into typed `EmailProviderResult` failures.
- Protection against cross-instance module-level API-key leakage.
- Network-free unit and optional-extra smoke tests.

## Compatibility

No new root-level PyCRMKit exports are introduced.

The existing `EmailProvider`, `EmailDeliveryService`, SMTP provider, Jinja2 renderer, and stable CRM 0.1/0.2/0.3 facade remain compatible.

## Dependency boundary

```bash
pip install pycrmkit
```

still has no runtime dependency on Resend.

Use:

```bash
pip install "pycrmkit[resend]"
```

for the provider adapter.

## Deferred

`0.4.0rc1` remains responsible for delivery events, Communication persistence/history, and integrated mapping of provider callbacks such as delivered/opened/clicked/bounced outcomes.
