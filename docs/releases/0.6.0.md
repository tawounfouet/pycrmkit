# PyCRMKit 0.6.0 — Persistence Foundation Stable

`0.6.0` promotes the fully qualified `0.6.0rc1` persistence line to stable
without adding new persistence functionality.

The stable release combines SQLAlchemy repositories, explicit Unit-of-Work
transactions, PostgreSQL as the production-reference backend, versioned Alembic
migrations and installed-wheel qualification into one compatibility-governed
persistence foundation.

## Stable persistence stack

```text
Stable CRM facade 0.1–0.5
          ↓
Repository contracts
          ↓
SQLAlchemy repositories
          ↓
SQLAlchemy Unit of Work
          ↓
PostgreSQL
          ↓
Alembic migration head 0002
```

The domain and facade layers remain ORM-neutral. Applications can continue to
use the Memory adapter while production integrations can bind the same
repository contracts to SQLAlchemy/PostgreSQL.

## Stable scope

The `0.6.x` stable persistence line includes:

- SQLAlchemy 2.x persistence models and explicit Domain ↔ ORM mappers;
- repository adapters for CRM Core, Activity/Timeline, Sales, Communication,
  Audit and Webhooks;
- one shared SQLAlchemy Session per Unit of Work;
- explicit commit and rollback ownership;
- post-commit domain-event publication;
- PostgreSQL 17 production-reference qualification;
- database-enforced normalized uniqueness where required by repository
  contracts;
- backend-neutral PostgreSQL/SQLAlchemy error translation;
- Alembic-managed schema evolution;
- packaged migration CLI through `pycrmkit-migrate`;
- migration head `0002`;
- installed-wheel PostgreSQL and migration smoke qualification.

## Repository contract stability

The Memory, SQLite/SQLAlchemy and PostgreSQL adapters are qualified against the
same observable repository behavior.

The RC qualification exposed and removed backend-only preconditions caused by
cross-aggregate database foreign keys.

The following remain reference IDs rather than persistence-ownership FKs:

- `Lead.contact_id`;
- `Lead.organization_id`;
- `Opportunity.contact_id`;
- `Opportunity.organization_id`;
- `WebhookDelivery.subscription_id`.

Ownership relations remain database-enforced, including nested Communication,
Webhook-attempt and Tag-assignment persistence.

## Transaction contract

The stable SQLAlchemy Unit of Work guarantees:

- all repositories in one UoW share one Session;
- repositories never commit independently;
- leaving an uncommitted context rolls back;
- exceptions roll back pending writes;
- explicit rollback keeps the UoW usable;
- repeated commit is rejected;
- domain events are published only after the database commit succeeds;
- subscriber failure after commit cannot undo committed database state.

The release qualifies multi-repository rollback and the major transactional CRM
flows on PostgreSQL.

## PostgreSQL contract

Install the PostgreSQL adapter dependencies with:

```bash
pip install "pycrmkit[postgresql]"
```

The production-reference backend is qualified for:

- constraints and indexes;
- Unicode and timezone-aware datetime values;
- Decimal precision;
- JSON and Custom Fields;
- transaction boundaries;
- concurrent uniqueness races;
- normalized database exceptions.

## Migration contract

Install migration tooling with:

```bash
pip install "pycrmkit[migrations]"
```

For a fresh database:

```bash
export PYCRMKIT_DATABASE_URL='postgresql+psycopg://crm:secret@localhost:5432/crm'
pycrmkit-migrate upgrade head
pycrmkit-migrate current
pycrmkit-migrate check
```

The stable migration history is:

```text
0001  persistence baseline
  ↓
0002  align repository reference semantics
```

Released revisions are immutable.

Existing `0.6.0b3` databases at `0001` upgrade to `0002` without dropping
CRM data. Existing pre-Alembic `0.6.0b2` databases must first be verified
against the baseline, stamped at `0001`, then upgraded to head.

## Installed-package qualification

The stable persistence gate validates the artifact that consumers actually
install:

1. build the wheel;
2. create a clean virtual environment;
3. install the wheel with migration/PostgreSQL dependencies;
4. invoke the packaged `pycrmkit-migrate` CLI;
5. migrate an empty PostgreSQL database to head;
6. run `current` and `check`;
7. execute a CRM + Sales persistence smoke through the installed package.

This confirms that both Python code and migration assets are present in the
wheel.
