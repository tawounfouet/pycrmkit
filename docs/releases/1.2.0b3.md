## Overview

This beta extends the existing `crm.campaigns` facade with optional HTTP exposure over FastAPI and Django REST Framework and provider-neutral direct-member import/export. The core remains headless; no web stack or ORM is required by a core-only installation.

Campaign HTTP endpoints are **opt-in**, protected by an explicitly configured host-authenticated principal resolver and authorization policy. Unsigned `X-Actor-ID` headers never grant Campaign identity or permission. Existing non-Campaign routes keep their prior compatibility behavior; they are **not** retroactively protected by this new boundary.

## Delivered scope

### HTTP: FastAPI and DRF parity

- Campaign create, list, retrieve, PATCH and lifecycle (activate, complete, archive), with optimistic revision preconditions.
- Direct Campaign member list/add/remove.
- Deduplicated audience list and count across direct members and captured Segment sources.
- Segment source attach/refresh/detach and captured provenance.
- Attribution reference list/add/remove and CommunicationRecord **link metadata** list/link/unlink.
- Host-owned action/resource/scope authorization, bounded pagination (1 to 200), typed input schemas and standardized errors.
- Negative tests for forged actor headers, unauthorized list counts and private CommunicationRecord content.
- Cross-transport rendered JSON parity tests across FastAPI and DRF against the same Memory-backed CRM.

**Not in scope:** messaging/email delivery, marketing automation, attribution scoring, campaign journeys, full CommunicationRecord content endpoints, an HTTP file-upload interface or cross-tenant filtering performed after pagination.

### Data Operations: Python API

- `import_campaign_members(...)` consumes existing `CSVReader`, `JSONReader`, `JSONLReader`, `ImportReader`, `ImportReport` and mapping primitives. This is a bounded (1-1000 rows) **direct membership only** operation.
- Duplicate detection is based on existing **direct** members and successfully inserted rows. Existing captured Segment members are not classified as direct duplicates; Segment snapshots are never mutated.
- Missing CRM entity references are row validation failures. Unexpected business/storage errors propagate; earlier successfully committed rows can remain. There is no global batch transaction or exactly-once promise.
- `export_campaign_records(..., kind="direct"|"audience"|"sources", format="csv"|"json"|"jsonl")` reads bounded facade pages and uses the existing exporters. The audience export is deduplicated, but **not snapshot-consistent during concurrent writes**.

### Backend coverage

- Memory, SQLAlchemy/PostgreSQL and native Django Campaign persistence use the existing `crm.campaigns` contract.
- No new persistence tables or migrations in b3. The earlier Alembic `0006_campaign_persistence` and Django `0004_campaign_persistence` / `0005_communication_record_store` retain ownership. The physical SQLAlchemy and Django Segment-source schemas are **not interchangeable** and must not be migrated by both tools against one physical schema.
- The earlier frozen public `ImportPipeline` dataclass shape and `ImportStage` enum remain unchanged.
