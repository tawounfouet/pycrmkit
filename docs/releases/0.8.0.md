# PyCRMKit 0.8.0 — Django Integration Stable

`0.8.0` promotes the fully qualified Django release candidate to stable
without adding new functional Django scope.

## Stable integration line

The stable Django path is:

```text
Django 5.2
  ↓
Django admin + optional DRF
  ↓
PyCRMKit CRM facade
  ↓
DjangoTransactionBridge
  ↓
Django repositories
  ↓
PostgreSQL 17
```

The framework-agnostic core remains independent of Django and DRF.

## Stable scope

```text
PyCRMKitDjangoConfig
pycrmkit_crm app label
Contact Django persistence + repository
Organization Django persistence + repository
Relationship Django persistence + repository
Django migration 0001_initial
DjangoTransactionBridge
Django admin helpers
optional DRF serializers/ViewSets/router
offset pagination bridge
request-context propagation
domain/request error mapping
Django + PostgreSQL reference application
clean installed-wheel Django/PostgreSQL E2E
```

## Deployment contract

Django schema evolution remains explicit:

```text
install package + required extras
    ↓
configure PYCRMKIT_DATABASE_URL
    ↓
python manage.py migrate
    ↓
python manage.py check
    ↓
start Django application
```

PyCRMKit never applies Django migrations implicitly at import or startup.

## Compatibility baseline

The stable line is qualified with:

```text
Python 3.11
Python 3.12
Python 3.13
Django >=5.2,<6
Django REST Framework >=3.18,<4
PostgreSQL 17 reference E2E
```

The plain core wheel remains installable without Django or DRF. The plain
`django` extra remains installable without DRF.

## Stable HTTP/DRF contract

The documented DRF surface for the persisted Django aggregate families remains:

```text
Contacts
Organizations
Relationships
```

The stable contract includes documented router paths/methods, serializer
conversion semantics, omitted-vs-null PATCH behavior, offset pagination,
`X-Actor-ID` / `X-Correlation-ID` propagation and the public error mapping.

## Transaction contract

`DjangoTransactionBridge` retains:

```text
explicit commit
rollback on uncommitted exit
exception rollback
explicit rollback-and-continue
ambient transaction/savepoint participation
domain-event publication only after actual commit
```

When nested inside an outer `transaction.atomic()`, staged events are deferred
with Django `on_commit()` semantics.

## Scope boundary

Stable does not mean every PyCRMKit domain module now has Django persistence.

The stable `0.8.x` Django persistence scope remains intentionally limited to:

```text
Contacts
Organizations
Relationships
```

Therefore `DjangoTransactionBridge` is not advertised as the complete
cross-domain PyCRMKit `UnitOfWork`.
