# PyCRMKit 0.9.0a1 — External Identities

`0.9.0a1` starts the Data Operations line with a provider-neutral mapping
between upstream record IDs and PyCRMKit entities.

## Delivered

```text
external_identities/entities.py
external_identities/services.py
external_identities/repository.py
crm.external_identities
Memory repository
SQLAlchemy/PostgreSQL repository
Django repository
Alembic 0003
Django 0002_external_identity
shared adapter contract
PostgreSQL round-trip qualification
Django/PostgreSQL round-trip qualification
```

## Public facade

```python
identity = crm.external_identities.attach(
    contact,
    system="hubspot",
    external_id="123456",
)

resolved = crm.external_identities.resolve(
    "hubspot",
    "123456",
)

page = crm.external_identities.list_for_entity(contact)

crm.external_identities.detach(
    "hubspot",
    "123456",
)
```

## Identity invariant

The alpha defines one upstream record by:

```text
(system, external_id)
```

A pair belongs to one PyCRMKit entity.

Same-owner replay is idempotent. Different-owner attachment raises
`external_identity.owner.conflict`.

## Persistence

SQLAlchemy production schemas advance:

```text
0001
 ↓
0002
 ↓
0003 external identities
```

Django schemas advance:

```text
0001_initial
 ↓
0002_external_identity
```

Both migration paths are explicit and packaged.

## Qualification

The repository contract is replayed on Memory, SQLAlchemy and Django. The
PostgreSQL persistence qualification attaches and reloads an external identity
through a fresh CRM/runtime. The Django reference application performs the same
external-identity round trip across separate Python/Django processes.

## Scope boundary

This alpha does not yet introduce row readers, mapping rules, normalization
pipelines, validation reports or bulk import execution.

Those belong to **`0.9.0a2 — Import Framework`**.
