# PyCRMKit 1.0.0a1 — Public API Freeze Candidate

`1.0.0a1` begins the V1 production-stabilization cycle.

The release adds no major CRM domain capability. Its purpose is to turn the
existing V0.1–V0.9 surfaces into an explicit candidate compatibility contract.

## Reviewed surface

The freeze review covers:

```text
CRM facade
entities and value objects
DTO/update/query types
typed exceptions
repository protocols
UnitOfWork
event names
event serialization
configuration/context
persistence adapter entry points
FastAPI integration
Django/DRF integration
email provider entry points
Data Operations APIs
```

## Classification

Every reviewed surface is classified as:

```text
public
provisional
internal
```

Public candidate APIs are intended to enter the V1 compatibility promise.

Provisional APIs remain usable but may still change before V1 stable.

Internal APIs remain implementation details even when technically importable.

## Executable API contract

The candidate manifest is:

```text
tests/compatibility/public_api_v1_candidate.json
```

The compatibility test is:

```text
tests/compatibility/test_public_api_v1_candidate.py
```

The dedicated CI gate is:

```text
.github/workflows/public-api-freeze.yml
```

The gate validates the contract from both the source checkout and the built
wheel in a clean environment.

## Root and facade freeze

The shallow root API remains:

```python
from pycrmkit import CRM, CRMConfig, CRMContext, __version__
```

The facade freezes the namespace/method inventory accumulated through the
stable V0 releases without exposing the concrete `pycrmkit.facade.*`
implementation classes.

## Domain exports

The bounded-context package `__all__` surfaces for CRM Core, Activities,
Sales, Communication, Eventing/Webhooks and Data Operations are captured
exactly by the manifest.

An accidental export removal, rename or addition now fails the freeze test and
requires an explicit compatibility decision.

## Repository contracts

The public domain-owned repository protocols and `UnitOfWork` are captured as
V1 extension points.

Adapter implementation detail is deliberately separated from these contracts.

## Events and serialization

The candidate freezes:

```text
BUILTIN_EVENT_TYPES
DomainEvent field names
EventSerializer round-trip envelope
external_identity.attached
external_identity.detached
```

The audit action `contact.merged` remains classified separately from domain
event types.

## Adapter boundary

Public candidate adapter entry points include Memory/SQLAlchemy transaction
entry points and the documented FastAPI, Django/DRF and provider integration
surfaces.

ORM models, mapper mechanics and migration implementation modules are not
promoted into the V1 public domain API.

## Scope boundary

No new:

