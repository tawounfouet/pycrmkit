# PyCRMKit 0.7.0b1 — Routers

`0.7.0b1` turns the transport/dependency foundation delivered in
`0.7.0a1` into a reusable FastAPI HTTP surface.

## Objective

The release adds FastAPI routing without changing the dependency direction of
the framework:

```text
FastAPI
   ↓
Integration Layer
   ↓
CRM Facade
   ↓
Domain
```

The core remains usable without FastAPI or Pydantic.

## Added

- `create_crm_router(factory)` composite router factory;
- Contacts router;
- Organizations router;
- Relationships router;
- Activities router;
- Tasks router;
- Leads command router;
- Opportunities command router;
- Timeline read router;
- FastAPI integration tests for the combined HTTP surface.

## Router composition

A consuming application mounts the integration under any prefix:

```python
from fastapi import FastAPI

from pycrmkit import CRM
from pycrmkit.integrations.fastapi import create_crm_router

crm = CRM.memory()
app = FastAPI()
app.include_router(create_crm_router(lambda: crm), prefix="/crm")
```

Storage selection remains outside the router layer. The same API surface can be
wired to Memory or SQLAlchemy/PostgreSQL through the CRM factory.

## Architectural invariant

Every endpoint follows:

```text
request
  ↓
router
  ↓
schema
  ↓
CRMDependency
  ↓
CRM facade
  ↓
domain/service
```

No router imports or receives:

```text
SQLAlchemy Session
ORM model
repository implementation
Unit of Work implementation
```

## Domain commands remain explicit

Lifecycle transitions are modeled as commands rather than generic CRUD:

```text
archive contact
end relationship
start / complete / cancel / reopen task
qualify / disqualify / convert lead
move opportunity
```

This keeps HTTP semantics aligned with the domain facade.

## Leads and Opportunities

The public Lead facade currently exposes:

```text
create
qualify
disqualify
convert
```

The public Opportunity facade currently exposes:

```text
create
move
```

`0.7.0b1` mirrors that public surface. It intentionally does not reach through
`CRM._runtime` to expose repository-level reads.

## Pagination

Contacts, Organizations, Relationships, Activities, Tasks and Timeline use the
existing bounded `OffsetPageRequest` semantics and serialize results through
`PageResponse`.

## Qualification scope

The beta adds TestClient coverage for:

- router registration;
- HTTP creation/read/update/list flows where the facade supports them;
- domain command endpoints;
- pagination;
- Activity/Task → Timeline composition;
- Lead → Opportunity conversion and stage movement;
- request context propagation.

The release remains subject to the normal repository quality gates before
merge.
