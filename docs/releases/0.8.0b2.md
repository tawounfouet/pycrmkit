# PyCRMKit 0.8.0b2 — Optional DRF

`0.8.0b2` adds an optional Django REST Framework transport on top of the
framework-agnostic PyCRMKit facade.

## Delivered

```text
separate pycrmkit[drf] extra
Contact serializers + ViewSet
Organization serializers + ViewSet
Relationship serializers + ViewSet
reusable SimpleRouter factory
application-owned CRM factory setting
offset pagination bridge
actor/correlation header propagation
domain error bridge
normalized DRF request errors
dedicated DRF CI
clean-wheel DRF API smoke
Django-without-DRF dependency-boundary smoke
```

## Dependency boundary

```bash
pip install "pycrmkit[django]"
```

does not install DRF.

```bash
pip install "pycrmkit[drf]"
```

adds Django REST Framework explicitly.

## Transport architecture

```text
HTTP
 ↓
DRF serializer / ViewSet
 ↓
CRM facade
 ↓
domain services
 ↓
UoW / repository contracts
 ↓
selected adapter
```

The ViewSets never call Django models or repositories directly.

## API surface

The reusable router covers Contacts, Organizations, and Relationships, matching
the currently qualified Django aggregate scope. List routes preserve the
stable offset pagination contract, PATCH preserves omitted-vs-cleared update
semantics, and archive/end actions call the existing public facade commands.

## Error contract

PyCRMKit domain errors retain their `code/message/context` payload and map to
the same public HTTP status semantics used by the other HTTP adapter.

DRF request-validation errors are normalized as
`request.validation_error`; submitted input is not echoed.

## Qualification

The dedicated gate validates serializers, router/API flows, request context,
pagination, domain errors, request errors, clean-wheel installation and the
optional dependency boundary.

The full reference Django application and Django/PostgreSQL E2E remain
**`0.8.0rc1`** scope.
