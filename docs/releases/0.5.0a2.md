# PyCRMKit 0.5.0a2 — Correlation & Causation

This alpha defines causal trace propagation for event-triggered CRM mutations.

## Propagation rule

For a child operation caused by a parent `DomainEvent`:

- `actor_id` inherits the parent actor;
- `correlation_id` preserves the parent correlation identifier;
- if the parent has no correlation identifier, its event ID becomes the root;
- `causation_id` is the direct parent event ID.

The rule is available through both `CRMContext.from_event(event)` and
`crm.with_event(event)`.

## Multi-hop semantics

```text
A correlation=request-1 causation=None
B correlation=request-1 causation=A
C correlation=request-1 causation=B
```

This is the trace model later webhook infrastructure can transport and observe.

## Compatibility

Stable `0.1`–`0.4` facade behavior remains unchanged.
`with_context(...)` continues to support explicit context overrides.
`DomainEvent` serialization preserves actor, correlation and causation in the
existing public envelope.

## Deferred

Webhook registrations begin in `0.5.0b1`. Delivery/signing/retry
infrastructure remains scheduled for `0.5.0b2`.
