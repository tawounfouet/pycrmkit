# PyCRMKit 1.0.0b1 — Security & Privacy Hardening

`1.0.0b1` hardens the V1 public API candidate for production-facing security
and privacy behavior.

No new CRM aggregate or persistence schema is introduced.

## Hardening scope

The milestone verifies:

```text
PII-safe logging/diagnostics
secret handling
webhook signatures
input validation
destructive action safeguards
duplicate merge safeguards
event payload redaction
```

## Privacy changes

Public error serialization now redacts sensitive context keys recursively.

FastAPI and DRF error bridges use the same redaction behavior.

Core contact validation no longer copies malformed email/phone values into
error context.

External Identity errors no longer expose the external record identifier in
their error context.

Merge primary-contact-point conflict errors no longer expose the competing
email or phone values.

## Event changes

`external_identity.attached` and `external_identity.detached` keep their
event names but their payload is minimized from:

```text
system + external_id
```

to:

```text
system
```

The external identifier remains accessible through explicit CRM data APIs.

## Webhook hardening

Webhook signing continues to use HMAC-SHA256 and constant-time comparison.

`verify_webhook_signature()` now supports optional freshness validation using:

```text
current_timestamp
tolerance_seconds
```

The legacy four-argument integrity-only call remains valid.

Webhook subscriptions gain audited secret rotation through:

```python
crm.webhooks.rotate_secret(...)
```

The old/new secret values are never written into audit changes.

Webhook subscription/request representations also exclude URL/body/header/key
material that could leak through diagnostics.

## Merge hardening

A merge now rejects provenance containing a `blocking` conflict even if the
provided decision has been constructed as `duplicate`.

Existing protections remain unchanged:

```text
explicit primary
explicit duplicate
matching provenance
duplicate decision required by default
conservative conflict policy
transactional rollback
duplicate archival
PII-minimized audit
```

## Destructive operations

The public facade continues to expose lifecycle actions rather than generic hard
delete:

```text
archive
end
disable
detach
merge
```

Security tests lock this boundary.
