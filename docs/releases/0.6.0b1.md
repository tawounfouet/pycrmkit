# PyCRMKit 0.6.0b1 — Unit of Work & Transactions

`0.6.0b1` moves transaction ownership from individual SQLAlchemy repository
adapters into a shared Unit of Work.

## Added

- `SQLAlchemyUnitOfWork`;
- one shared SQLAlchemy `Session` across every repository in the transaction;
- explicit commit and rollback semantics;
- rollback on uncommitted context exit;
- rollback on exceptions;
- staged post-commit domain-event publication;
- rejection of repeated commit on the same transaction;
- post-commit subscriber qualification;
- bulk-write transaction qualification;
- SQLAlchemy facade E2E coverage for Lead conversion and Pipeline transitions.

## Required transactional flows

The implementation-plan flows are now qualified:

```text
lead conversion          ✅
contact merge foundation ✅
pipeline transition      ✅
bulk write foundation    ✅
```

The contact merge item is a transaction foundation only. No new merge facade or
domain API is introduced in this release.

## Event semantics

Events remain inside the UoW until the database commit succeeds.

A subscriber failure after commit may propagate to the caller, but it cannot
undo the committed database state. Follow-up subscribers can open a fresh UoW
and read the committed state.

## Compatibility

The stable `0.1`–`0.5` domain/facade surface remains unchanged.

SQLAlchemy stays optional and is only imported when the SQLAlchemy adapter
package is used.
