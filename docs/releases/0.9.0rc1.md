# PyCRMKit 0.9.0rc1 — Data Operations E2E

`0.9.0rc1` qualifies the complete V0.9 data-operations line before stable
promotion.

No new domain capability is introduced by this release candidate.

## Integrated scenario

The reference journey is:

```text
import contacts
detect duplicates
review candidates
merge
export normalized result
verify audit/provenance
```

This directly implements the V0.9 release-candidate scenario defined by the
implementation plan.

## Import qualification

The scenario uses a CSV source and composes:

```text
CSVReader
RecordMapper
RecordNormalizer
RequiredFieldsValidator
ImportPipeline
application-owned ImportPersister
MemoryUnitOfWork
ContactService
```

It verifies successful Contact creation plus one rejected invalid row.

## Deduplication qualification

Committed Contacts are exposed through a repository-backed
`CandidateSource`.

The scenario verifies:

```text
candidate discovery
email signal
phone signal
full-name signal
score = 100
decision = duplicate
DedupProvenance preservation
```

## Merge qualification

The reviewed provenance is passed directly into `MergeService`.

The scenario verifies:

```text
explicit primary selection
duplicate archival
external identity ownership transfer
contact.merged audit
audit provenance decision
MergeResult provenance continuity
```

The conservative policies introduced in `0.9.0b3` remain unchanged.

## Export qualification

The resulting active contacts are emitted and read back through:

```text
CSVExporter  ↔ CSVReader
JSONExporter ↔ JSONReader
JSONLExporter ↔ JSONLReader
```

The round-tripped records must exactly equal the normalized export projection.

## Clean-wheel E2E

The dedicated workflow builds the release artifacts and executes the same
reference scenario in a fresh virtual environment using only the generated
wheel.

`PYTHONPATH` is cleared for the installed-wheel execution.
