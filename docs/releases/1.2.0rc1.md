## Release overview

`1.2.0rc1` is a production **qualification candidate**, not a new Campaign product or the stable `1.2.0` release. It freezes and qualifies the Campaign 1.2 feature line implemented through the preceding 1.2 alpha and beta releases:

- Campaign metadata, lifecycle and optimistic revision preconditions;
- direct members and deduplicated audience across captured Segment sources;
- attribution references and CommunicationRecord **link metadata**, not email/message delivery;
- opt-in FastAPI and Django REST Framework Campaign HTTP surfaces with explicit host-authenticated authorization;
- bounded CSV/JSON/JSONL direct-membership imports, with repeatable recovery and honest partial-write semantics;
- paginated CSV/JSON/JSONL direct/audience/source exports and privacy/consistency boundaries;
- Memory, SQLAlchemy/PostgreSQL and native Django adapter persistence, migrations and concurrency qualification.

No new Campaign schema migration, marketing automation system, durable outbox or bundled identity provider is introduced in this RC.

## 3. Security and operational limits

All nine milestone risk tickets [#103](https://github.com/tawounfouet/pycrmkit/issues/103)–[#111](https://github.com/tawounfouet/pycrmkit/issues/111) received exact-SHA qualification/acceptance comments and were closed as risk-qualification trackers before merge. Closure **does not mean these design limitations disappeared**:

- Host applications must provide real IAM/OIDC, trusted principal resolution, tenant authorization for every exposed route, database TLS, key management, auditing and rate limits. PyCRMKit does not implement an IAM or multi-tenant security service.
- A Campaign member import may leave earlier rows committed after a later failure; replays deduplicate direct members only. There is no blanket exactly-once or atomic-batch promise.
- Offset-based export is not guaranteed to provide a transactionally consistent audience snapshot during concurrent writes.
- For CSV that users may open in spreadsheets, the consuming host **must** apply or validate an anti-formula policy; generic CSV output does not automatically neutralize malicious formulas. A tested host guard is provided at `examples/data_operations/campaign_csv_spreadsheet_guard.py`.
- Synthetic CI performance and query-plan baselines are not production latency or throughput SLAs. The signed FastAPI reference host uses test-owned tenant mappings and ephemeral credentials; it is not production authentication software.
- Django and SQLAlchemy/Alembic manage their **own** physical schemas. Do not point both migration engines at a shared incompatible Campaign schema.

The prior audit [NO-GO report](../development/1.2.0rc1-go-no-go-assessment.md) records the *pre-merge state* of the project and is retained for traceability; its publication hold was superseded after source-main qualification and the verified GitHub prerelease.
