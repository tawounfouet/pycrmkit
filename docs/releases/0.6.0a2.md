# PyCRMKit 0.6.0a2 — Repository Adapters

`0.6.0a2` delivers the repository layer on top of the SQLAlchemy persistence foundation introduced in `0.6.0a1`.

## Added

The implementation-plan repository scope is now available for:

- Contacts
- Organizations
- Relationships
- Activities
- Tasks
- Leads
- Opportunities
- Pipelines

The adapter inventory also covers the persisted boundaries already introduced by the stable `0.1`–`0.5` lines:

- Tags and Tag assignments
- versioned Custom Fields and current values
- Timeline projections
- Audit history
- Communication intents, attempts, CRM records and delivery events
- Webhook subscriptions, delivery state and attempt history

## Contract semantics

The SQLAlchemy adapters preserve the observable repository semantics already established by the Memory adapter:

- typed not-found and duplicate/conflict errors;
- deterministic ordering and exact offset pagination;
- normalized query filters;
- append-only/idempotent history where the domain requires it;
- versioned Custom Field schema history;
- webhook subscription/event and delivery-attempt idempotency;
- exact typed-ID round trips for Timeline `EntityReference` values.

Repository writes are session-scoped. They deliberately do **not** call `commit()` internally so transaction ownership can move cleanly into the SQLAlchemy Unit of Work in `0.6.0b1`.

## Persistence model corrections

Qualification exposed two persistence details that are now explicit:

1. Custom Field definition revisions use the composite identity `(id, schema_version)`.
2. Timeline references persist the concrete identifier class in addition to `kind` and UUID, because `EntityReference` permits any `UUIDId` subtype and equality must survive a database round trip.

## Qualification

The SQLAlchemy adapter suite is exercised against isolated SQLite sessions while the production PostgreSQL milestone remains deferred.

The release passes:

- repository conformance suites;
- targeted Communication persistence qualification;
- Python 3.11, 3.12 and 3.13 tests;
- Ruff;
- strict mypy;
- documentation build;
- package build;
- the aggregate CI workflow.

## Next milestone

The next planned delivery is **`0.6.0b1 — Unit of Work & Transactions`**.

That milestone will introduce `storage/sqlalchemy/unit_of_work.py` and transactional qualification for flows such as Lead conversion, pipeline transitions and bulk-write foundations. PostgreSQL, Alembic and full persistence qualification remain scheduled for `0.6.0b2`, `0.6.0b3` and `0.6.0rc1` respectively.
