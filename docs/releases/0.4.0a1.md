# PyCRMKit 0.4.0a1 — Communication Domain

## Objective

Start the `0.4.x` Communication line with domain semantics only.

The release implements the architectural split between communication intent, delivery attempt, and CRM communication record before introducing any concrete email provider.

## Added

- `CommunicationIntent` with typed identity, recipients, content, CRM references, idempotency context, and explicit draft/queued/cancelled lifecycle.
- `DeliveryAttempt` with typed identity, attempt number, provider metadata boundary, and pending/accepted/failed lifecycle.
- `CommunicationRecord` for CRM history, intentionally separated from full message bodies and provider implementation details.
- Email-first `CommunicationAddress` normalization plus recipient/content value objects.
- Unit tests for lifecycle, timestamp, validation, duplicate-recipient, and privacy-boundary behavior.
- Smoke coverage for the provisional Communication-domain imports.

## Compatibility

The stable `0.1`, `0.2`, and `0.3` CRM facade namespaces remain unchanged. The new provisional domain surface is imported from `pycrmkit.communication`; the root package remains intentionally shallow.

## Architectural boundary

No provider adapter is part of this alpha. In particular, this release intentionally does not expose `crm.email.send(...)` yet.

## Deferred

- `0.4.0a2`: Email Provider Protocol.
- `0.4.0b1`: templates and stdlib SMTP.
- `0.4.0b2`: Resend adapter.
- `0.4.0rc1`: delivery events/history and Communication E2E qualification.
