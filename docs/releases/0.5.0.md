# PyCRMKit 0.5.0 — Eventing & Webhooks Stable

`0.5.0` promotes the fully qualified `0.5.0rc1` Eventing & Webhooks line to
stable without adding new functional scope.

## Stable scope

The stable `0.5.x` line now includes:

- version-aware public event registry;
- deterministic canonical event serialization;
- actor, correlation and causation propagation;
- persistent webhook registrations and exact event filtering;
- HMAC-SHA256 request signing and verification;
- provider-neutral webhook transport;
- standard-library HTTP transport;
- conservative public-destination and redirect policy;
- deterministic retry/backoff;
- idempotent delivery identity per subscription/event pair;
- append-only delivery-attempt history;
- dead-letter terminal state;
- explicit delivery/retry/history facade APIs;
- automatic post-commit EventBus → webhook delivery;
- Memory persistence for subscriptions, deliveries and attempts.

## Stable facade surface

```text
crm.webhooks.register
crm.webhooks.disable
crm.webhooks.list

crm.webhooks.deliver
crm.webhooks.retry_due
crm.webhooks.deliveries
crm.webhooks.attempts
```

Event-triggered work also retains:

```text
crm.with_event(...)
CRMContext.from_event(...)
```

The complete compatibility contract is documented in
`docs/api/0.5-public-api.md`.

## Stable delivery path

```text
CRM mutation
    ↓
commit source transaction
    ↓
DomainEvent
    ↓
WebhookEventBridge
    ↓
matching subscription
    ↓
canonical serialization
    ↓
HMAC signature
    ↓
WebhookTransport
    ↓
response / retry schedule
    ↓
delivery + attempt history
```

Automatic bridging remains enabled by default for `CRM.memory(...)`.
Applications can opt out with `webhook_auto_delivery=False` and continue to
use explicit `crm.webhooks.deliver(event)`.

## Reliability contract

A delivery is idempotently identified by:

```text
(subscription_id, event_id)
```

Terminal successful/dead-letter deliveries are not resent by replaying the same
event for the same subscription.

Retryable conditions include network/timeouts, HTTP 408, 425, 429 and 5xx.
Other 3xx/4xx responses are terminal for the current delivery.

## Security boundary

Webhook payloads are signed as:

```text
v1=HMAC_SHA256(secret, "<unix_timestamp>.<canonical_payload_bytes>")
```

The built-in stdlib transport rejects redirects and non-public destinations by
default. Private-network delivery requires explicit opt-in.

Signing secrets remain excluded from entity representations and audit changes.
Delivery logs retain normalized metadata rather than response bodies or raw
exception messages.

## Transaction semantics

Memory source state commits before synchronous post-commit subscribers execute.
The Memory transaction boundary is released before subscribers run, allowing
subscriber-owned follow-up Unit-of-Work transactions against committed state.

## Deferred scope

Production SQLAlchemy/PostgreSQL persistence begins in `0.6.x`. Durable
cross-process outbox/claiming and distributed delivery coordination also require
production persistence semantics and are not part of the Memory-focused
`0.5.x` contract.

The next implementation milestone is **`0.6.0a1 — SQLAlchemy Foundation`**.
