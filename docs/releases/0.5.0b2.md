# PyCRMKit 0.5.0b2 — Webhook Delivery Engine

This beta adds the explicit delivery engine on top of the persistent
subscription model introduced in `0.5.0b1`.

## Added

- canonical event payload delivery through `EventSerializer`;
- HMAC-SHA256 request signing and verification;
- provider-neutral `WebhookTransport`;
- standard-library HTTP POST transport;
- conservative public-destination policy and redirect rejection;
- deterministic exponential retry/backoff;
- retryable timeout/network/408/425/429/5xx policy;
- terminal non-retryable 3xx/4xx handling;
- idempotent delivery identity per subscription/event pair;
- append-only attempt history;
- dead-letter terminal state;
- explicit facade APIs for delivery, due retries and history.

## Delivery state

```text
PENDING
   ↓
attempt
   ├── 2xx ───────────────► SUCCEEDED
   ├── retryable failure ─► RETRY_SCHEDULED
   │                           ↓
   │                       retry_due()
   │                           ↓
   └── terminal/exhausted ─► DEAD_LETTER
```

Each delivery retains the canonical serialized event payload so retries remain
possible after the originating callback returns.

## Idempotency

The stable beta identity is:

```text
(subscription_id, event_id)
```

A replay of a terminal delivery does not produce another HTTP request.
All attempts for one delivery retain the same opaque
`X-PyCRMKit-Idempotency-Key`.

## Security

Signing secrets are excluded from entity representations and audit changes.
Delivery logs store safe status/error codes, not response bodies or raw
exception messages.

The stdlib transport rejects non-public destinations and redirects by default.
Private-network delivery must be enabled explicitly. Network egress controls
remain recommended for production.

## Qualification

The beta is covered by signing vectors, signature tamper rejection, retry
schedule tests, timeout/5xx retry, terminal 4xx, dead-letter behavior,
idempotent duplicate delivery, Memory repository contracts, facade E2E, a real
local HTTP transport boundary, and installed-package smoke.

## Deferred

Automatic CRM event publication → webhook dispatch is intentionally reserved
for `0.5.0rc1`, which owns the complete Eventing & Webhooks E2E scenario.
