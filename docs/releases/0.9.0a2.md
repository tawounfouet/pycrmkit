# PyCRMKit 0.9.0a2 — Import Framework

`0.9.0a2` adds the format-neutral data-import foundation for the `0.9.x` Data
Operations line.

## Delivered

```text
importers/base.py
importers/mapping.py
importers/normalization.py
importers/validation.py
importers/reports.py
importers/pipeline.py
```

The pipeline is:

```text
Read
 ↓
Map
 ↓
Normalize
 ↓
Validate
 ↓
Deduplicate
 ↓
Persist
 ↓
Report
```

## Contracts

The alpha introduces protocols for:

```text
ImportReader
ImportMapper
ImportNormalizer
ImportValidator
ImportDeduplicator
ImportPersister
```

The default reader accepts any iterable of mapping-shaped records. Physical
formats remain outside this release.

## Mapping and normalization

`FieldMapping` and `RecordMapper` translate provider-owned source fields into a
canonical target shape. Mapping can rename fields, provide defaults, explicitly
ignore fields and optionally preserve unmapped values.

`RecordNormalizer` applies ordered per-field rules. Built-in helpers cover
whitespace trimming, Unicode-aware case folding and blank-text normalization,
and custom callables can be composed.

## Validation and reporting

Validation returns structured issues rather than mutating input. The release
ships required-field, predicate and composite validators.

Every `ImportReport` exposes:

```text
rows_read
rows_created
rows_updated
rows_skipped
duplicates
validation_errors
```

alongside row-level status, duplicate disposition, persisted entity ID and
machine-readable validation details.

## Failure policy

Row-level mapping/normalization/validation failures are reported and skipped.
Duplicate-detector and persistence failures propagate to the caller rather than
being silently converted into a successful-looking report.

## Scope boundary

This alpha does not add:

```text
CSV reader/writer
JSON reader/writer
JSONL reader/writer
dedup scoring/candidates
merge execution
```

These remain scheduled for `0.9.0b1`, `0.9.0b2` and `0.9.0b3`.
