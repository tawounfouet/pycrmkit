## 3. Scope and contract freeze

**Promote the already qualified 1.2 Campaign Metadata capabilities, never add a new Campaign product.** Frozen candidate contract groups:

- Core CRM compatibility 1.0/1.1: facade, published signatures, DTO and Value Objects, errors, event names and payloads, and existing segmentation/SavedQuery/Sales Task/Business Calendar surfaces.
- Campaign domain: entity identity, owner, status, optimistic revision, lifecycle, direct membership, captured Segment sources, union/deduplicated audience, stable ordering/count and metadata-only attribution/CommunicationRecord links.
- Optional HTTP: FastAPI OpenAPI/DTO and DRF serializers/golden responses, error/status mapping, PATCH absent/null/value distinction and tenant-aware host authorization boundaries.
- DataOps: bounded CSV/JSON/JSONL direct-member imports, explicit partially committed recovery/replay; paginated direct/audience/source exports without snapshot guarantees during churn.
- Storage contracts: Memory, SQLAlchemy/PostgreSQL, native Django ORM, UoW/repository semantics, migrations with separate Alembic/Django schema ownership.
- Distribution: Python 3.11–3.13 declared, core-only without optional framework dependencies; wheel/sdist, packaged migration resources and optional extras.

**Strict exclusions until a separately approved later release:** new Campaign fields/required schema, journeys, bulk delivery, marketing automation, global IAM/OIDC, automatic multi-tenant isolation, exactly-once import, transactionally consistent export snapshots, provider-specific implementation in the core, schema redesign, rewriting old migrations.

**Allowed between RC and stable:** release/test/docs/packaging adjustments and minimal fixes for demonstrable blocking correctness/security/compatibility defects. Each exception must have issue, reason, regression test, impact analysis and full requalification; a material API or behavior change requires considering `1.2.0rc2`. No silent legacy manifest edits or tag moves.

**Design concepts applied:** Domain-Driven Design bounded context, Ports & Adapters / Hexagonal Architecture, Dependency Inversion, Separation of Concerns, Repository + Unit of Work, Contract Testing, SemVer with PEP 440, immutable release/provenance, risk-based release gates.
