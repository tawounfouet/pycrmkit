# PyCRMKit 1.2.0 — LOT-32-005 DataOps Replay, Export & Spreadsheet Safety

**Branch:** `release/1.2.0-campaign-metadata-stable`  
**PR:** [#113](https://github.com/tawounfouet/pycrmkit/pull/113) (Draft)  
**Scope:** stable qualification only; no new Python public API, runtime change, migration or version flip.

## Frozen behavioral boundaries

- Imports support **CSV, JSON arrays and JSONL** via `CSVReader`, `JSONReader`, `JSONLReader`, and `import_campaign_members`.
- Preflight buffers **max_rows + 1**, rejecting malformed sources and the 1001st row before any Campaign membership write. The hard limit remains 1000 rows.
- Each valid **direct** Campaign member commits independently through the CRM facade. On a repository failure, already committed rows may survive. Replaying the full source skips existing direct memberships and creates the remaining rows. This is **logical deduplication**, not distributed exactly-once execution or a file-wide Unit of Work.
- Error counters, row numbers, stage and error codes are observable integration contracts. With `retain_row_results=False`, the aggregate report intentionally does not retain errors or untrusted raw rows.
- Captured Segment membership is not direct membership. The import must not modify source snapshots.

## Stable export acceptance

| Kind | Exact canonical columns | Disclosure policy |
|---|---|---|
| `direct` | `campaign_id,entity_kind,entity_id,source,added_at` | Direct membership provenance |
| `audience` | `campaign_id,entity_kind,entity_id` | Audience identifiers only |
| `sources` | `campaign_id,segment_id,segment_revision,entity_kind,attached_at,captured_at,member_count` | Segment capture provenance |

The three kinds use CSV, JSON and JSONL with cross-format semantic parity. The exported count is emitted rows; do **not** claim point-in-time snapshot consistency under concurrent mutations. Offset pagination is best-effort without an external mutation freeze/consistent database snapshot.

Exports must omit contact name/email, recipient and Communication content, actor identities, raw metadata and secrets. **IDs, timestamps and provenance remain confidential and can be personal data**. A trusted host must authorize actor, tenant, Campaign, purpose, storage ACLs, retention and deletion before invoking the Python API.

## Spreadsheet safety and file publication

Canonical CSV preserves the domain-normalized `source` without spreadsheet-specific escaping; even correctly quoted cells beginning with `=`, `+`, `-`, `@`, or variants after Unicode NFKC and leading whitespace normalization can be interpreted as formulas. The **consumer-side** `validate_campaign_csv_for_spreadsheet` example fails closed; it must not silently mutate the canonical export. This example is not a blanket Excel/LibreOffice security certification.

Publish only after a complete export and accepted spreadsheet validation: write to restricted temporary storage, validate the entire file, then atomically promote; quarantine or remove files after validation or I/O failures. Use a typed-text import or a separately transformed review copy if operationally appropriate. Never open an untrusted canonical CSV directly in a spreadsheet.

## Residual risks / stable decision

1. Concurrent imports may raise unique conflicts; a retry requires verified direct-membership state and cannot fabricate success.
2. Streaming exports can leave incomplete files. Callers own cleanup, access controls and atomic publication.
3. Offset-based exports are **not** snapshots. Audit-grade exports require host-level consistency coordination.
4. CSV formula protection is consumer-managed; guard rules are conservative and do not certify every spreadsheet parser.
5. Python DataOps entrypoints do not implicitly enforce HTTP IAM or tenant isolation.
