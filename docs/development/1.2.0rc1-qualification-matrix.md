## Version-bearing artifact policy

- Distinguish CI-generated **pre-merge RC-labelled artifacts** (LOT-31-015) from the **post-merge exact-main rebuild** (LOT-31-016).
- `SOURCE_DATE_EPOCH`, sdist normalization, binary digests and release manifests are controlled by LOT-31-016. An archive hash is valid only for its exact archive bytes; a later commit or rebuild might yield different digests.
- The `Campaign RC1 Distribution Qualification` workflow must assert the **rc1** filename and metadata and upload the RC-labelled archive from its exact HEAD.
- The `Campaign RC1 Production Host Installed Wheel E2E` workflow must install the RC-labelled wheel, apply its migrations and run the tenant-security scenario against real PostgreSQL.
- Historical `publish-v1.2.0b2.yml` and `publish-v1.2.0b3.yml` must **not be edited or reused** for this candidate.

## Risk register / non-claims

This release does NOT implement general-purpose tenant isolation, IAM, JWT/OIDC, durable event delivery/outbox, scalable streaming-file upload, atomic import of all rows, concurrent-snapshot export or guaranteed production p95 response latency. Host authorization is a required integration responsibility. See `docs/development/1.2.0rc1-risk-register.md`.

## Release authority

Only LOT-31-016 can mark **GO** and, after branch-protection review, merge PR #112, rerun required CI on merged source, create and verify an immutable annotated tag, upload wheel/sdist plus checksums and release manifest, and publish the prerelease. If any required source, CI, security, API freeze or artifact validation gate fails, the outcome is **NO-GO**, without a tag or release.
