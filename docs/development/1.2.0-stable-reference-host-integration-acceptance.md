# PyCRMKit 1.2.0 — LOT-32-007 Reference Host Integration Qualification

**PR:** [#113](https://github.com/tawounfouet/pycrmkit/pull/113), DRAFT/OPEN.  
**Branch:** `release/1.2.0-campaign-metadata-stable`.  
**Scope:** acceptance of the existing signed FastAPI reference application against an **installed `1.2.0rc1` wheel**, a migrated, disposable PostgreSQL 16/17 backend, and real ASGI TestClient requests. This is *not* deployment of an IAM platform.

## Design and contract boundaries

The reference host is intentionally **outside** the frozen PyCRMKit domain: host-owned trust boundary, action/owner authorization before facade creation, reference-ownership preflight, limited exposure of Campaign HTTP routes, and deny-by-default generic writes. This is Ports & Adapters, an explicit Security Boundary, Defense in Depth, Contract/E2E Testing and the Repository / Unit of Work pattern.

No global JWT, RLS, OAuth2, OIDC, object-level authorization for all CRM APIs, durable outbox, or guaranteed batch transaction is introduced. A signed *synthetic* HMAC bearer token with short expiry is only a test fixture. The `CommunicationRecord.metadata["tenant"]` marker is **not** authoritative production IAM evidence.

## Reproducibility and safe operational model

[Dedicated workflow](https://github.com/tawounfouet/pycrmkit/blob/release/1.2.0-campaign-metadata-stable/.github/workflows/campaign-stable-reference-host-qualification.yml) uses independent PostgreSQL service jobs for versions **16** and **17**, `POSTGRES_HOST_AUTH_METHOD=trust` **only in throwaway CI containers**, per-scenario random HMAC key generated only within the local step process (not written to GITHUB_ENV or displayed), and a clean installed wheel with migration resources. Do not point this scenario at production systems or copy CI database authentication policy.

## Non-claims and risk acceptance

- The host DataOps endpoints verify referenced resources **before** calling the existing library importer; this proves the bounded reference host's fail-before-write preflight for the tested invalid/foreign rows. It does **not** turn PyCRMKit's general importer into a transactionally atomic batch engine.
- The host's export endpoint uses a bounded in-memory response. Offset pagination under concurrent mutation remains best effort; it is not a snapshot.
- The reference host protects only its mounted Campaign/host routes. Other generic CRM routes, direct Python scripts, scheduled jobs and background integrations require independent production authorization.
- A mixed-tenant audience introduced by **out-of-band direct access** must not be assumed filtered automatically on read. Production hosts must enforce tenant isolation for all data paths and revalidate ownership if untrusted mutations can occur.
- The CI synthetic tenant marker on a Communication record is not reliable identity; durable provider delivery, content privacy controls, encrypted export storage, key rotation, rate limiting, PII retention and GDPR measures are host duties.
