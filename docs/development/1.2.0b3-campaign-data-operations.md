## 1. Architecture and compatibility

The module `pycrmkit.campaigns.data_operations` exposes an import runner using existing `ImportReader`, `ImportRow`, `ImportReport`, `ValidationIssue`, `PersistResult` and existing CSV/JSON/JSONL readers/exporters. It is inspired by `segments/data_operations.py` but deliberately uses a **narrow Campaign runner** instead of modifying `ImportPipeline`: the public fields of that v1 class are frozen by a compatibility manifest. Its generic semantics remain unchanged.

All persistence calls are made through `crm.campaigns`. There are no raw repository, SQLAlchemy or Django ORM calls. This module is agnostic to FastAPI and DRF.

## 2. Direct member import

```python
from pathlib import Path

from pycrmkit.campaigns import import_campaign_members
from pycrmkit.importers import CSVReader

report = import_campaign_members(
    crm.campaigns,
    campaign_id,
    CSVReader(Path("campaign-members.csv")),
    source="crm-batch-2026-10",
)
print(report.as_dict())
for issue in report.errors:
    print(issue.row_number, issue.stage, issue.code)
```

Canonical CSV columns:

```csv
entity_kind,entity_id
contact,00000000-0000-4000-8000-000000000011
organization,00000000-0000-4000-8000-000000000012
```

Supported entity kinds: `contact`, `organization`, `lead`, `opportunity`. IDs are UUIDs of **existing** CRM entities. The target `campaign_id` and import `source` are passed through trusted Python configuration, never supplied by an untrusted row. An optional `RecordMapper` adapts source headers to canonical fields.

JSON array and JSONL use the same canonical object keys. Instantiate `JSONReader` or `JSONLReader` instead of `CSVReader`; the rest of the call is identical.

### Import safety, replays and counters

- Default and absolute initial limit: **1000 input rows**, with `max_rows` configurable only between 1 and 1000. A bounded preflight reads at most 1001 rows, so oversized or syntactically malformed files fail before any membership mutation.
- The Campaign is resolved and checked for archival before ingesting rows.
- UUID/kind/required-field/mapper errors are reported against the **data row number** (starting at 1, not the physical CSV line).
- A valid UUID referencing a nonexisting CRM entity is a recoverable **row validation failure**. Its code is `campaign.member.not_found` and its report stage is `validate`, even though existence is checked by the domain service within the persistence attempt.
- A direct member already present in the Campaign, or repeated successfully within the same file, becomes `skipped` with `duplicate=True`. Captured Segment audience membership does **not** make a row a direct duplicate.
- Replaying a completed file does not create second logical direct memberships. First-run results (created) and later replay results (skipped) can differ.
- Each accepted member commits through the existing public facade. There is **no global transaction, no durable idempotency key, and no distributed exactly-once guarantee**. Fatal failures, including archived Campaign, unexpected business constraint, concurrent unique conflict and database outage, propagate. Earlier committed rows can remain.
- Concurrent unique membership conflicts are intentionally **not** converted into successful skips without a fresh verified direct-membership check; the current conservative behavior is to propagate the conflict.
- The in-memory deduplication pre-scan reads the existing **direct** member list in bounded pages; its index can grow with existing Campaign member count. This is a synchronous bounded-input first version, not an infinite scale job.
- When `retain_row_results=False`, counters persist, but row-level error evidence is intentionally not retained.

## 3. CSV / JSON / JSONL export

```python
from pathlib import Path
from pycrmkit.campaigns import export_campaign_records

count = export_campaign_records(
    crm.campaigns,
    campaign_id,
    Path("direct-members.csv"),
    kind="direct",
    format="csv",
    page_size=100,
)
```

For a live audience and captured Segment provenance use `kind="audience"` or `kind="sources"`; formats `csv`, `json` and `jsonl` are supported.

| Kind | Fields |
|---|---|
| `direct` | campaign_id, entity_kind, entity_id, source, added_at |
| `audience` | campaign_id, entity_kind, entity_id |
| `sources` | campaign_id, segment_id, segment_revision, entity_kind, attached_at, captured_at, member_count |

Records are streamed page by page through `crm.campaigns.members`, `audience`, or `segment_sources`, and serialized by existing exporter classes. `page_size` is 1–200, default 50. UUIDs serialize as canonical strings and aware timestamps as ISO 8601 strings. CSV emits a header even if no rows exist. No full CommunicationRecord content, PII, actor IDs or audit logs are automatically exported.

**Consistency qualification:** offset pagination is stable under an unchanged dataset; concurrent writes may change page composition. These iterators do not promise transactional snapshot consistency. CSV consumers should treat cell content as untrusted if custom source strings are supplied; spreadsheets may interpret leading formula characters, so the consuming application should apply suitable anti-formula policies.
