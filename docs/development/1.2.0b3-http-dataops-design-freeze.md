## 2. Frozen architecture and ADRs

### ADR CAMP-HTTP-001 - Separate, explicit HTTP exposure

**Decision:** Introduce Campaign opt-in assembly. FastAPI integrates a Campaign router explicitly (or via a backwards-compatible opt-in argument); DRF exposes Campaign only through an explicit opt-in registration. Existing Segments, Saved Queries and v1.1 REST routes keep their prior configuration and behavior. The path prefix `/crm` remains host-owned; Campaign paths begin with `/campaigns`.

**Why:** The existing composite bridges set request context from unsigned headers. Auto-registering a protected Campaign surface without security configuration would create an accidental remote-access path.

### ADR CAMP-HTTP-002 - Shared logical REST contract, separate framework schemas

**Decision:** Pydantic request/response models and DRF serializers adapt the same domain contract, with shared golden JSON fixtures. They never return QuerySets, SQLAlchemy rows, Django models or domain objects directly to the wire. Serialize UUIDs as strings, aware times as UTC ISO 8601, enums as values, metadata as JSON. Request extras are forbidden where supported.

### ADR CAMP-HTTP-003 - Security boundary: fail closed

**Decision:** A Campaign router requires an application-supplied, trusted principal resolver and action/resource authorization policy at assembly/configuration time. Missing integration, anonymous principal or policy failure never means allow.

Contract proposal (typing details to be stabilized in LOT-30-003):

```python
principal = identity_provider(request)  # From trusted host auth, NOT X-Actor-ID
if principal is None:
    raise NotAuthenticated()            # 401
policy.require(principal, action="campaign.read", campaign_id=campaign_id, scope=scope)
# Raises PermissionDenied (403); success permits facade execution only.
crm = crm_factory().with_context(actor_id=principal.actor_id, correlation_id=safe_request_id)
```

- The host is responsible for verifying JWT/session/other auth and constructing a principal.
- `X-Actor-ID` is untrusted and must never override authenticated actor provenance.
- For individual objects, check object permission before disclosure; missing resources and policy responses must not leak other Campaigns.
- A list/search policy must authorize the **entire requested scope** *before* `crm.campaigns.list`; do not post-filter paged results and leak total counts. If this cannot be proven, deny the list route. Campaign ownership filters are not a generic tenant-isolation mechanism.
- Different explicit permissions apply to `campaign.list`, `read`, `create`, `update`, `lifecycle`, `members.read`, `members.write`, `sources.read`, `sources.write`, `attribution.read`, `attribution.write`, `communications.link`, `communications.content.read`, `data.import`, `data.export`.
- `audience/count` requires audience-read authorization: cardinality is information.
- `communication-links` is metadata-only; full `CommunicationRecord` payloads are **not publicly exposed in the initial b3 route registry**. Adding them requires capability + separate sensitive-data permission.
- `X-Correlation-ID` is trace metadata only: enforce syntax and length cap, generate a trusted server value if missing/invalid, never log secrets/PII.
- Rate limiting and request body ceilings are the host's deployment responsibility, with documented hooks/constraints; no unbounded HTTP file upload.
- FastAPI and DRF both distinguish 401 (unauthenticated) and 403 (authenticated but disallowed). Default existing routes are not retroactively modified by this scoped ADR.
- Unit and integration tests must prove unconfigured policy, forged actor header, cross-Campaign read, list counts and export attempts fail closed.

### ADR CAMP-HTTP-004 - PATCH and concurrency

**Decision:** `PATCH /campaigns/{id}` has `expected_revision: int >= 1` **required in the JSON body**, as do the POST lifecycle action bodies. Pydantic `model_fields_set` and DRF `validated_data` key presence must be translated into `CampaignUpdate(UNSET...)`; an explicitly supplied `null` stays `None` if the domain permits clearing. `status`, `key`, `revision`, `id` and timestamps are not editable fields. Status transitions are separate `POST /activate`, `/complete`, `/archive`. Revision conflicts map to 409, never silent overwrite.

### ADR CAMP-HTTP-005 - Action shapes and HTTP errors

**Decision:** `POST /campaigns` -> 201; metadata GET/list -> 200; PATCH/lifecycle -> 200; POST add-members -> 200 with typed member array (parity with existing Segments); POST attach source / add attribution / link Communication -> 201 when newly created; removal operations -> 200 with `removed`; invalid input -> 422; not found -> 404; conflict/invalid lifecycle -> 409; unavailable adapter capability -> documented integration error, no fabricated success. Domain error payloads reuse the existing integration convention. Explicit HTTP authentication failures are 401/403, not domain `ValidationError`.

### ADR CAMP-HTTP-006 - Direct membership only for imports

**Decision:** Campaign import affects **direct members only**. It must never refresh, overwrite or delete captured Segment snapshots. Campaign ID comes from trusted import configuration. Canonical input fields are `entity_kind` and `entity_id`; kinds belong to the supported segmentable set. Provenance `source` is injected from the caller's validated operation context, not an arbitrary per-row override.

### ADR CAMP-HTTP-007 - Partial import and error classification

**Decision:** First increment is synchronous, bounded, per-row persistence through `crm.campaigns`. A trusted Python caller configures a maximum number of input rows (proposed default 1000, larger limits require an explicit tested policy). There is **no global batch atomicity**, no distributed exactly-once guarantee, and no durable idempotency-key store.

- Row format / UUID / kind problems are validation failures with precise row indexes.
- A nonexistent target entity may be a row-local rejected result; missing Campaign, unauthorized request, archived Campaign and database/integration outages are **fatal** to the import, not success or silent skip.
- A direct-member duplicate is `skipped/duplicate` whether repeated within the file or already persisted. Audience membership solely via a captured Segment **does not** establish direct-member duplication.
- An unexpected persister failure **must propagate**, with partial-commit behavior documented. Existing `ImportPipeline` does not catch persister errors, so Campaign must either add a backwards-compatible explicit `PERSIST` reporting stage or own a narrow runner with equivalent `ImportReport` counters. Never convert all persister exceptions to success, never swallow a DB outage.
- Concurrent unique conflicts are classified as duplicates only after verified direct membership exists; otherwise treat as conflict/fatal.
- Replays must never create two logical direct memberships. They may produce created -> skipped, but do not promise identical reports across replays.

**Gate:** Tests of all of the above before public `import_campaign_members` is advertised as replay-safe.

### ADR CAMP-HTTP-008 - Export scope and consistency

**Decision:** Provider-neutral iterable exports for direct members, final audience, and Segment-source provenance. Use `OffsetPageRequest` with `1 <= page_size <= 200` and stable sort as defined by repositories. Final audience is deduplicated and must not pretend to have a unique source; membership and capture provenance remain separate. Reuse CSV/JSON/JSONL export components. Sensitive fields (actor, communication content) are excluded by default unless explicit separate permission/redaction policy exists.

**Consistency:** Offset paging is deterministic under an unchanged dataset, **not** a transactionally frozen snapshot under concurrent writes. Do not claim stronger guarantees without a proven snapshot design.

### ADR CAMP-HTTP-009 - Migrations and existing APIs

**Decision:** No new database schema/migration for b3 by default. Do not mutate Django `0004`, `0005` or Alembic `0006`. Run Django migration drift checks and Alembic checks; SQLAlchemy and Django must not independently own one physical Campaign schema. Avoid breaking existing composite router call signatures.

### ADR CAMP-HTTP-010 - Optional dependencies and rollout

**Decision:** Core `pip install pycrmkit` must remain independent of FastAPI/DRF imports. Campaign HTTP classes live only in optional integration modules; Campaign DataOps helpers are provider-neutral. Version remains `1.2.0b2` until b3 release-prep gate; do not prematurely tag `v1.2.0b3`.
