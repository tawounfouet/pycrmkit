## 6. Scope freeze and change-control decisions

**Freeze effective for the rc1 work branch:** no new Campaign features, no additional transports, no marketing automation, no unrelated refactoring, no new public API family, no breaking change to the V1 compatibility manifest and no speculative persistence redesign.

Allowed only when supported by a risk, gate or blocking defect: regression fixes, security/privacy corrections, contract conformance, tests, E2E host examples, performance regression fixes, documentation, release tooling and packaging corrections. Every correction must record affected public semantics and its own fresh qualification.

Candidate architectural decisions to document and qualify (not yet all implemented as tests):

1. **ADR-CAMP-RC-001** - Feature freeze: stability first; no scope expansion.
2. **ADR-CAMP-RC-002** - Host-authenticated identity/authorization required before read, list/count and mutations.
3. **ADR-CAMP-RC-003** - Semantic portability across Memory/SQLAlchemy/Django, without invented capabilities.
4. **ADR-CAMP-RC-004** - Explicit partial import failures and logical replay idempotence, not exactly once.
5. **ADR-CAMP-RC-005** - Offset export limitation: no consistent concurrent snapshot promise.
6. **ADR-CAMP-RC-006** - CSV spreadsheet and privacy risks have explicit policy and tests.
7. **ADR-CAMP-RC-007** - One schema owner: Django **or** Alembic, never both for shared physical Campaign tables.
8. **ADR-CAMP-RC-008** - Release identity = qualified exact source SHA, reproducible artifact bytes, verification, annotated tag.
